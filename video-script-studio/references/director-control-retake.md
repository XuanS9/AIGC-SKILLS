# 导演控制与返工：用最小改动修失控维度

吸收 Seedance 分镜师 3.0 的控制图选型、帧源追踪、五出口返工与证据审核方法。输出、命名、审批和模型能力以 `video-script-studio` 为准，配合 [导演编译](director-compiler.md)。这不是强制控制图阶段，也不自动执行外部生成。

## 1. 控制图按风险选，不按镜数配

先问“去掉这张图，哪一镜的哪个关系会失控？”答不出就不加。以下是内部路由标签，不是平台能力等级、固定人数阈值或成功承诺：

| 级别 | 具体风险 | 最小控制选择 |
|---|---|---|
| L1 文字/资产直通 | 简单动作，地标与姿态已能写清 | 已有资产＋文字布局，不加图 |
| L2 构图/落点 | 开场构图、接触姿态、起止状态必须精确 | 可用单帧；确需多个状态再核验模式是否支持关键帧序列 |
| L3 站位/交换 | 多人交错、持物交接、视线目标易串 | 同机位站位参考，必要时分镜角度帧 |
| L4 动线/遮挡 | 复杂穿行、运镜轨迹、遮挡关系难以只靠文字表达 | 预演或白模/深度参考；实际模式支持后才提交 |

- L3 不自动比 L2 好，L4 不保证成功；控制只覆盖有风险的镜头和时段，不铺满全片。
- 参考图数量、支持模态、关键帧绑定、编辑和延长均查实际模型/模式资料。未核验的能力只作候选，不用来源包的参数或“最稳人数”覆盖本地规格。
- 宫格优先作为生产/选帧工具；选中格需检查分辨率、身份与构图，再决定裁切或同源重建。不把多格板默认当视频第一帧。
- 俯视地图默认用于人读布局；若要投喂，先核验模式和职责，防生成俯视构图。代码草图能核空间，不证明最终身份、材质或动作质量，用户没要求不强制制作。

## 2. 帧源与作用域

每份控制参考在 `project.md` 对应 Clip 的依赖/交接处记录：

`Clip/时间段｜控制目标｜源文件与版本｜布局版本｜用途｜实际文件/绑定状态｜依赖`

身份仍以资产总表为准；控制参考如需注册调用名，沿用总表现有参考登记方式和中文名，不新建 `ctrl-*` 编号体系或第二资产索引。

帧源三选一：
1. **复用**：已有图满足当前角度与状态，直接引用对应版本。
2. **新构图**：按已确认资产/布局写图像提示词，标待生成；不声称控制图已经齐备。
3. **前片截帧**：先等依赖 Clip 生成，再从实际结果取帧，核对动作相位、身份和运动模糊。当前只登记待回填项，不用臆造首帧代替实际尾帧。

防止控制参考污染成片：
- 身份图管身份，场景图管几何/材质/环境，站位或深度图只管指定几何关系，动作视频只管所选动作/运镜；在【参考素材职责】明确采用属性和时间范围。
- 场景图的拍摄角度不是固定机位；只有明确选为构图/关键帧控制时才继承其构图。
- 图中有本片不需的字母、色块、人物或格线，先在块外说明清理/裁切/替换；正文采用正向关系，不把污染物反复写进禁令。
- 关键帧、身份图和场景图有冲突时先定位冲突，不许模型自行仲裁。文字定稿可保留，但有冲突的绑定不得标可提交。
- 变更回到可追溯的原始参考或已确认干净基准，避免反复回喂有缺陷的中间图；新版本保留历史，更新当前绑定，只复核受影响 Clip。

## 3. 返工先收证据，不先堆词

最小收案：**哪条/哪版｜何时/哪里不对｜期望与实际差异｜已有尝试及结果**。只补问缺失且影响诊断的信息，已有记录不重复问。次数未知写未知，不当成第一次。

读取对应提示词、确认分镜、总表/布局和用户提供的当前结果。图能读则读图；视频无法查看就请给相关帧或时间段描述，明确“据用户描述，未核实画面”，仍可提供条件性修复样本。找不到原提示词可给诊断与重建候选，不把素材缺失伪装成已经对照。

先分：源图本身错、词义冲突、镜头过载、局部生成瑕疵，还是上游因果/空间就不成立。只改一类变量，以便下一次验证归因；同一根因要求同步文件不算多变量实验。

## 4. 五个修复出口

| 出口 | 适用证据 | 最小修复与回写 |
|---|---|---|
| 改词 | 动作终点、时序、主次运动或声源歧义 | 保留其他条件，改明确动作/落点/并发关系；四段式重交受影响样本 |
| 局部编辑/延长 | 主体与整体演出成立，只有局部对象、声音或尾部节拍错 | 核验编辑/延长能力；写修改对象、时间范围、变化和保留项；不承诺原片绝对不变 |
| 换镜头设计 | 动作过载、接触不可读、空间被遮挡或时长容不下 | 调机位、拆因果链或重分 Clip；先更新规划，用户确认受影响样本后展开，不擅删已确认剧情 |
| 改输入 | 身份/结构/特殊姿态不对，参考缺角度或带污染 | 基于干净基准补角度/状态衍生图，保留稳定 handle，更新实际 file/version 与绑定 |
| 回上游 | 文字布局矛盾、资产设计不满足动作、剧情逻辑断链 | 指明源文件、原句与受影响范围，先修最早出错的依据，再重编相关下游 |

大范围空间颠倒、整条因果顺序错、一镜到底被拆、开场换身份或后半段整体失控，不靠局部补丁掩盖。画面符合指令但戏不成立，回到人物任务/观看任务，而不是加强“电影感”。

不设“必须先重抽”或“抽满15–20次才换镜”门槛。明确文本/参考错误先修；确无已知结构问题且用户接受成本时才建议再取一版。连续无改善或同一关键问题两轮仍不能定位，列已试证据、剩余选项与建议，请用户选择，不无限循环。

## 5. 证据审核与依赖回写

沿原有交付关卡检查五类问题，不另增加用户审批：

| 类型 | 例 | 返回位置 |
|---|---|---|
| 矛盾 | 光源/数量/身份/布局两处不一致 | 对应源文档或编译错误处 |
| 断链 | 持物凭空转移、上一条未落地下一条重演 | 分镜接点与状态记录 |
| 走样 | 行为失去原人物目标，声音/风格偏离确认稿 | 导演工作单/表演或样本 |
| 能力风险 | 未绑定标签、无依据时长、模式不支持控制输入 | 绑定表与模型能力核验 |
| 硬约束违背 | 擅改确认台词/结局、超范围交付 | 确认稿与输出契约 |

问题记录统一：`对象/版本/时间段｜原文或画面证据｜期望值与实际值｜影响｜修复出口｜复验结果`。

文本失败先修复；未知事实标待核验，不能伪称通过。文案核对、真实绑定、已生成与视觉验收是四种状态。可用独立审核工具时传完整依据并让其只审不改；没有则单代理核对，不冒充 fresh 审核、不要求用户为工具缺失另批门禁。

修复在原路径留版本/变更记录，记录旧值、新值、原因、影响 Clip：
- 改落幅 → 核下一条起态，更新 `project.md` 场末快照/未解线头。
- 改布局 → 更新总表 `layout` 版本，相关场景/视频待复核，不动无关场景。
- 改素材 → 更新总表文件与实际绑定；逻辑 handle 不变，平台槽位映射按当前提交重核。
- 改镜序/片段 → 同步 Clip 编号和项目序列表，旧文本检查证据不再代表新版本。
- 未变部分保留确认，变更部分按既有样本流程处理。提示词包可交付不等于成片验收通过。
