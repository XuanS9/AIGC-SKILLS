# 样本确认与完整提示词生成

## 类型分流与强制顺序

先识别用户本次明确要求的提示词类型，再读取对应模块。两类任务均先执行 [项目资产总表](asset-registry.md)：读取同一份总表，样本与完整稿复用已登记名称；分批确认不分开命名。登记需求或展示名称映射不等于交付另一类提示词，也不增加确认轮次：

- 用户要求资产提示词：只写角色、道具、场景等资产提示词，不附视频提示词，不自动进入视频阶段。
- 用户要求视频提示词：只写视频提示词。可以引用已有资产、说明素材职责或缺项，但不附资产生成提示词，也不先替用户创作资产。
- 用户同时明确要求两类：建立两个独立批次，分开给样本、分开确认、分开交付；用户可以一次明确确认两个已展示的样本，但一类的确认不授权另一类。
- 类型无法从当前请求与上下文确定时，先询问要写资产还是视频提示词，不擅自两类都写。

**每次写提示词都必须执行：本次类型的样本 → 等待用户确认该样本 → 输出本次范围的所有提示词。**新创作、续写、整组扩写、改写、补镜、修词、局部修复以及只需一条提示词均适用。不得因风格已定、历史样本已通过、素材齐全或用户催促直接输出而省略本次样本确认；不设置“跳过样本”的快捷路径。已确认设定和参数可继承，不等于本次样本已获确认。

收到对本批次当前样本的明确确认后，立即交付该批次全部提示词，不在确认与交付之间再给样本形成循环。该批次交付完成后，新的提示词请求重新执行样本确认。模型咨询、预算、纯诊断等不写提示词的任务直接处理；一旦要交付新写或修改后的提示词，就进入此流程。此顺序优先于模块中直接交完整稿、默认三套完整动作方案及无附言等建议，原有功能、模型限制与正式格式继续保留。

## 1. 制作代表性样本

继承已确认的身份、剧情、素材职责、模型、画幅和风格，选择最能验证本次关键效果的一小部分。样本是可以独立使用的提示词，不是形容词清单、抽象方案或用省略号占位的半成品；完整指的是样本自身可执行，不是提前输出整组或全片。

| 任务 | 默认样本 | 主要确认内容 |
|---|---|---|
| 角色资产 | 选一个核心角色，先做一张正面或三分之四半身样本；保留可辨识面部、发型及关键服装材质 | 身份、造型、肤质/画风、光色与服装质感 |
| 道具资产 | 一个核心道具的代表性角度 | 形状、比例、结构、材质与使用状态 |
| 场景资产 | 一个代表性场景构图 | 空间层次、可行动区域、光源、色彩及材质 |
| 视频 | 一个代表性镜头或短片段，包含起始状态、动作与响应、可见结果、运镜和必要声音 | 动态风格、节奏、表演、镜头及连续性 |
| 用户明确同时要求资产和视频 | 两类分别选取代表性样本，分别注明本批次范围 | 各自确认，各自交付，不自动跨类型展开 |
| 已有视频编辑/延伸 | 选能体现修改效果或接续关系的局部片段 | 母片保留项、修改边界、首尾状态和接续效果 |

用户正在验证多视图排版、多个角色同框或某个复杂效果时，样本可包含验证它所需的最小完整组合，不能因缩小范围省掉被验证的关键部分。角色半身样本用于定风格，确认后的完整角色资产仍按六行、左侧面部与右侧无头三视图交付。

视频样本通常取约 5-8 秒的一段动作,具体时长按模型合法值和演出负荷确定,不作为固定模型参数;完整成片本就很短时取一个可验证的镜头,不强行截断关键动作或对白。全片时长不搬到样本上，样本取代表性短片段（约 5–8 秒）验证风格、不必凑满 30 秒；完整片段交付时才按默认向模型单次上限（约 30 秒）凑。当前项目默认 Seedance 2.5 视频生成按全能参考模式分配角色、道具、场景图及参考视频、音频的职责;用户已指定其他模型时先核对其实际输入能力;单张图片也只是参考,不自动成为视频起点。已有视频编辑/延伸若要求精确保留源时间线则核对平台实际能力;缺少必要素材时标明缺项,不虚构已上传的参考或可执行状态。

默认给一个推荐样本。剧情项目的场景资产与视频样本，按 [电影视觉参考匹配](higgsfield-style.md#电影视觉参考匹配) 标出具体电影主参考，并把光色、尺度、空间和材质落实到样本提示词；用户已指定电影直接继承，未指定则在样本中给出推荐，不增加独立风格确认轮次。只提供片名或“大片感”不足以完成样本。当前轮若仅维护 Skill，不因此启动项目提示词或索要样本确认。

仅当风格尚有实质分歧或用户要求比较时，给最多2–3个简短样本，每个只改变一类关键变量。动作任务先验证代表性交锋；默认三强度完整方案在样本确认后展开，标准/极速轴独立保留。只确认一种强度时，仅该强度视为已确认，不能声称其他版本也经用户验收。

## 2. 样本交付

普通文本输出按以下顺序：

1. **样本范围**：类型（资产或视频）、本批次范围、样本编号/版本、对象或片段、拟确认的风格；视频另列样本时长与全片目标时长，设置放在提示词外。
2. **样本提示词**：一个可复制代码块，写具体构图、主体、材质/光色或演出与镜头。仅使用真实存在的素材标签，沿用适用的身份、数量和无文字/水印约束。
3. **预期效果**：简述希望观察到的结果，明确这是预期；有实际结果时依据可见证据说明。
4. **确认请求**：例如“请确认这个样本的风格和预期效果；若需试生成，可把结果发来再确认。确认后我再展开完整提示词。”

交付样本后停止，等待用户回复；同一轮不附完整资产清单的全部提示词、全片演出稿或三套完整方案。不要先要求用户确认抽象方向、却不给可评估的样本。

用户要求纯 JSON 等严格格式时，样本按原生 schema 输出，不能擅加确认字段、破坏解析格式或附加不允许的文本。利用已有的标题/描述字段标明样本与待确认范围；没有合适字段时只交样本并等待用户，不输出完整批次。

当前环境只提供本地文本时，交付的是**样本提示词和预期效果**，不能声称已生成样图/样片或已通过视觉验收。用户可以明确确认文字方案并要求继续，此时标记“方案已确认，实际生成效果待验收”，不强制要求上传生成结果。若用户选择先看实际效果，则等待其提供样图/样片并确认，不自行把文字样本算作通过。

## 3. 确认、修改与展开

- 用户明确表示“确认，按这个继续”“采用样本A，展开完整提示词”等，才将本批次对应版本视为确认。仅收到素材、提问、修改意见、沉默或含糊的“继续看看”，不推定通过；两个类型都有待确认样本时，确认范围含糊则先澄清，不推定全部通过。
- 用户提出调整时，先修改本次样本并重新等待确认，不凭“按修改直接展开”略过修订样本。只请求修改一条时，该条修订稿可作为样本；确认后交付其正式可复制版本。
- 在当前会话中分别记录资产和视频的批次范围、样本版本、待确认/已确认/已交付状态及确认依据；继承主体身份、风格、素材职责与效果状态，不建额外数据库或向 skill 安装目录写项目记录。
- 确认后只交付对应类型、对应批次的全部提示词，使用原格式并继承样本规则。视频八栏目中的资产与参考锁定仅说明已有素材及主体，不夹带资产生成提示词；资产交付不附视频镜头提示词。不能只重复拉长样本或均分全片时长。
- 新一轮补镜、同类资产扩展、修词和局部修复也先给本次样本。保留此前已确认内容，只确认本次所需范围；资产完成不会自动开启视频流程，只有用户明确提出视频提示词请求才进入视频样本阶段。

## 交付前自查

是否已读取项目资产总表，并核对样本/完整稿中的调用名、正文名称和素材状态？是否只写用户本次要求的类型？样本是否标明本批次范围并能验证关键效果？是否避免虚构素材和生成结果？未获本次确认时是否只交了样本？完整交付是否有对应类型、批次及版本的确认依据？是否误用了历史确认或局部修改例外？原模块的格式、功能和模型限制是否仍满足？
