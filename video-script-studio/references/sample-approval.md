# 按场景推进：分阶段样本确认与文字布局交接

## 范围与确认

完整制作或同时要求多类提示词时，默认「统一规划 → 基础资产 → 场景 → 视频」，按场景或连续剧情段落建立批次，分阶段交付；不默认把所有类型一次写完。场景属于 S 类资产，只在制作流程上单独管理。只要基础资产、场景或视频时仅处理指定类型，不因缺项自动扩展任务。咨询、预算、纯诊断及 Skill 维护保持原任务范围。

各阶段读取 [项目资产总表](asset-registry.md)，继承同一份 `asset-registry.json` 的名称、文件、状态和布局。登记、提示词确认/交付、实际出图、视觉核对、平台绑定及生成结果验收分别记录；文字确认不能替代实图核对。

**CHECKPOINT：当前阶段样本（场景含文字空间底稿）→ 用户确认 → 完整交付当前阶段 → 下一阶段样本。**默认文字设定与布局确认后即可推进，不要求回传全部场景图或资产图；实图核对仅用于用户明确要求或出现明显偏差的相关范围。当前场景的视频完整交付后等待用户继续下一批，不自动展开后续场景。下一阶段仍有新内容样本确认，但不额外增加“是否允许切换阶段”的重复审批。

新写、改写、补镜、修词和单条交付均对新增/变化内容执行样本流程。每次修改后先按 [修改后标准复查闭环](production-checks.md#修改后标准复查闭环) 读回最终完整条目，核格式及受影响依赖/接缝；修复后重跑适用检查，再交付样本或已授权完整稿。收到当前样本确认后直接展开该确认范围；已确认且未变的资产、布局、提示词直接复用，不逐资产、逐镜重复审批。仅确认某一项时不扩展为整阶段通过。修改只重审受影响部分，并标记依赖它的下游待复核。

## 1. 统一规划与场景批次

1. 先继承/确定剧情、视觉风格、资产清单和场景动作需求，列简明批次目录：批次号、场景/连续剧情范围、预计 Clip 数、共享/新增资产与依赖。不在规划阶段提前展开全部提示词；已确认规划直接沿用。
2. 先确认近期批次需要的共享基础资产设定并交付提示词，再按每个场景的「补充基础资产 → 场景 → 视频」推进；已可复用的阶段直接跳过，不等全片资产齐备。
3. 一批以一个场景或连续剧情段落为主，长段按可交接的动作节点再分批。批次可含多个 Clip；Clip 保持根 SKILL.md 的“批-序”编号，阶段不占用 Clip 批次号，共享资产不另占视频批次。
4. 先登记所需角色、生物、道具、场景及职责，既有资产逐字复用 handle。基础资产与场景无依赖时可并行；存在体型、结构、可通行尺度依赖时，先协调文字设计。并行不免除样本确认，但不增加强制实图检查。
5. 场景与相关视频任务完整读取 [文字空间布局](spatial-layout.md)，在总表 `layout` 先锁定基准视点、地标数量/位置、连接关系、高差、通道、关键连接可见性及光向。场景正文必须写“什么在哪里、如何连接”，视频继承同版布局，不临时增设地标。只有文字时标“文字布局已确认，实图未核对”；未定义空间需先补设计，不能把设计当成实际观察。
6. 视频只引用本片段需要的资产和状态，资产目录不等于出场表。后续批延续当前末态、道具持有关系与场景变化。

## 2. 阶段样本与推进条件

每阶段先交一个或一组足以验证关键新设计的代表性样本，不提前附下游完整提示词。样本独立可复制，保留其完整版式和演出细节；已定稿共享资产只列复用。

| 阶段/任务 | 样本内容 | 文字确认重点（实图按需核对） |
|---|---|---|
| 基础资产：人类角色 | 单角色六行四格组板：唯一清晰面部特写＋正面/90°侧面/背面完整全身，全身格保留头部、不刻画五官；图底仅非文字波形，不附音色描述或标签；仅定脸/半身或全图无字按明确要求 | 身份、服装、版式、材质、比例与光色；直接继承原定风格，不默认真人或因出图偏差重选媒介；先查正向正文及附加模板有无跨媒介污染，不靠负面提示词修复。仅真人实拍分支核对定妆摄影、自然肤质及物理受光，其他分支核对对应线条/画材/渲染表现 |
| 基础资产：生物/植物 | 本体多视图及关键结构，保持完整轮廓 | 比例、斑纹、材质、结构与动作适配 |
| 基础资产：道具 | 主视图、补充角度和关键部件细节 | 形状、比例、连接、材质与持用方式 |
| 场景 | 环境图提示词，明确基准视点、环境地标位置与固定空间结构，整张无角色/生物/道具，与文字空间底稿对应 | 地标连接、通道、高差、场所用途、固定结构、空置通道、影视参考光色与剧情时段及动作可行性 |
| 视频 | 一个完整代表性片段，含剧情驱动的景别/机位、动作因果、必要的表情/道具/接触细节、声源、连续性和末态 | 与同版文字布局对应、每镜信息作用、细节可读性、机位/视线/路线、节奏、表演及交接 |
| 编辑/延伸 | 体现修改效果或接续关系的局部片段 | 母片保留项、修改边界、接点 |

基础资产/场景样本确认后交付当前阶段完整提示词，默认依靠已确认设定与文字布局进入下一阶段。图片未回传或助手未读图，不阻止文字定稿；块外简注“基于已确认文字布局，实图未核对”，不要求用户补传全项目图片，也不声称已出图或视觉通过。

关键设计未确认、任务依赖未知参考内容或已知图文冲突未解决时，受影响部分交条件性预稿并列具体假设。只有用户明确要求严格验收或报告偏差时才进入相关实图交接；只核对相关图片。仅视频请求不强制补做资产；用户明确选择纯文字生成且模式支持时按该路径核验，不伪造参考素材。

视频样本按 [导演分镜方法](directorial-shot-design.md#剧情驱动的多景别与多角度覆盖) 验证真实剧情的观察层次，不因是样本就默认固定广角；固定机位空间测试须标为专项测试，不替代正式剧情摄影样本。选择已确认剧情中的信息变化，按需要使用多角度、角色/道具/接触特写；不为了展示拍法擅加新道具、线索或故障，候选情节单独说明。无需另加逐镜审批，仍按当前样本整体确认。

视频样本默认选约5–8秒的完整动作段；用户指定测试完整 Clip 时按其要求，未另定时以接近30秒为编排目标，并核对模型/模式实际长度。样本时长不改写全片预算。

沿用 Seedance 2.5 `omni_reference` 的素材职责路由；没有可用参考时用中文名称与已知设定编写文字稿；设计未定才标条件性预稿，待素材/绑定另行注明。模型与规格放代码块外，视频代码块直接从四段式正文开始，运镜与时间戳内动作同步。风格在统一规划与相关阶段样本中按 [电影视觉参考匹配](higgsfield-style.md#电影视觉参考匹配) 转成光色、材质与空间设计，同一项目持续继承。

## 3. 当前阶段的标准交付顺序

1. **范围与版本**：批次、阶段、场景、样本/完整交付/条件性预稿状态；视频含 Clip 编号，必要的平台设置放块外。
2. **相关资产、布局与依赖**：既有复用、新增、修改、待生成、待视觉核对、待绑定分开列；附相关总表更新，不提前展开其他阶段提示词。
3. **当前阶段提示词**：基础资产仅新增/需修改的 C/B/P；场景仅 S；视频逐 Clip 完整四段式、连续时间戳与同等演出密度。各条独立代码块，人类六行、生物/道具多视图与各自背景规范保留，S类仅呈地形、建筑、固定结构和表面使用痕迹；角色/生物/道具落位归视频。
4. **核对与交接**：预期效果、文本/名称/lint/实图核对结果、未解决依赖与下一步。样本末请求确认；基础资产/场景完整提示词交付后按已确认文字设计交接下一阶段，视频完整交付后等待下一批；仅约定严格验收或出现已知冲突时等待相关核对。不得把预期效果写成实测结果。

未生成/未绑定的资产用稳定中文名称描述，规划 handle 留在清单；存在真实文件且核对当前绑定后才编译可提交标签。原生 JSON/HTML 按各自 schema 交付，审核与阶段说明放允许字段或块外。

按 [统一调用与验收总表](production-checks.md#统一调用与验收总表) 将适用模块及证据落到本轮样本/交付范围；人物样本也执行已有表演规范，短测试样本记录测试目的即可，不据此推定整片生成分组通过。不新增审批，已授权完整交付范围继续沿用。

## 4. 文字核对、定稿与按需实图诊断

- **基础资产文字关卡**：确认身份、造型、比例与结构设定，使其与动作/通道尺度相容；按需核对实际图片，不把未回传图当作文字流程阻塞。
- **场景文字关卡**：按 [文字空间布局](spatial-layout.md) 检查关键地标位置、连接、高差、通道和可见性是否写入场景正文，并检查视频机位与路线是否来自同版布局。画面左右随机位改变，固定连接关系不变。
- **视频关卡**：文字设定/布局已确认、相关文本检查通过即可文字定稿；未看图注明实图未核对，不承诺生成吻合。标“可提交”还须核验本 Clip 的真实平台绑定及模型/模式条件，并排除已知未解决冲突。绑定尚未完成时可为“文字定稿，待绑定”，不能称可提交；视频生成结果另行验收。
- **按需实图诊断**：用户明确要求或报告偏差时，仅核对相关图片；读取后记录实际证据，未读图则说明诊断仅依据用户描述。区分换机位造成的画面变化与真实布局冲突，优先修复妨碍关键动作的场景图，或经确认采用实际布局并同步文字，不要求补传所有场景图。
- **依赖回退**：上游文件换版或布局变更后，只标记相关下游待复核；核对无影响则保留原确认，有影响才修订样本。不能将旧版视觉通过记录移作新版证据，未受影响内容不重复审批。
- **缺素材/工具**：记录实际检查范围，标“未生成，视觉未验收”或具体待核状态；只做本地文本时提供生成交接，不声称完成外部生成、上传或绑定。

## 5. 快速联合预览（显式选择）

仅当用户明确要求快速预览、一起看整体方案或联合预稿时启用，不因同时请求多类提示词而自动启用。可给资产、场景与视频的配套样本，确认后展开用户约定范围的预稿，各用独立代码块。已确认未变的部分直接复用，局部确认不扩展范围。

联合确认只表示文字方案通过，不代替实图核对。确认布局并通过文本检查后可定稿文字视频方案，实图按需诊断；待生成/待绑定内容不能伪装成可提交素材。快速预览不改变稳定命名、总表、场景布局和连续性规则。

## 6. 项目记录

在 [项目工作区](project-workspace.md) 的 `project.md` 与 `asset-registry.json` 记录当前批次/阶段、交付模式、样本版本、确认范围与依据、文字布局版本、实际素材/绑定状态、按需视觉核对记录、设计阻塞、待复核下游、下一步。提示词存入项目 `prompts/`，不向 Skill 安装目录写项目记录。跨会话读回进度后从实际交接点继续，不把“提示词已交付”当作“实图已通过”，也不重新审批未变内容。
