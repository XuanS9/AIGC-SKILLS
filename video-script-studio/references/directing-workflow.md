# 导演编排与交付

资产与视频提示词分开写，只响应用户本次要求的类型，先执行 [样本确认流程](sample-approval.md)：每次交本次类型的代表性样本，等待用户明确确认，再展开对应批次全部提示词。新创作、改写、补镜、修词和单条交付均适用；继承已确认设定不等于复用历史样本确认，不设跳过例外。两类都被明确要求时分别给样本、确认和交付。以下完整稿、角色组板及三强度方案适用于对应批次确认后的阶段；确认后直接完成该批次，不重复确认或自动跨类型展开。


### 全包共用的导演编排

所有视频创作、改写、分镜、动作、编辑与延伸任务，先完整读取 [统一导演编排规范](narrative-planning.md) 与 [八栏目导演模板](template-general-director-2-5.md)。完整视频提示词默认按「资产与参考锁定→一句话总合成→全局视听与空间→主体行为与节奏规则→分段演出→连续性→结尾状态与交接→关键约束与排除」交付；创作或完整改写同时完整读取 [完整演出范本](template-full-performance-example.md)。具体动作与响应保留，视觉与动作的全局规则在一次生成内写一次，分段写行动与变化；独立分镜各自写本镜所需现场声，默认 NO BGM，跨镜音频连续性只列后期剪辑交接，验收留在内部；原生格式按统一规范映射，不重复附长稿。
精简必须保留关键时序绑定：动作同时/先后、触发条件、持续过程及跨段动作相位。能防止停步演表情、等待对方演完或重启动作的局部说明不作冗余删除，按统一规范核对删改前后是否等义。

按内容自动接入以下能力，无需用户点名模块：

- **人物表演**（包括动作、无对白和背景人物）：读取 [acting](higgsfield-acting.md) 人物档案、身体、眼神与验收规则及 [FACS 身体微反应](higgsfield-facs.md#physical-micro-beats--the-body-beyond-the-face)；精细表情、特写按需读取完整 FACS 工作流。细节与状态继承按统一规范执行。
- **剧情创作与改写**：读取 [scene-engine](higgsfield-scene-engine.md)，内部检查目标、障碍、策略、反转与价值变化的原定义及适用范围；专门审计时才展示审计报告，不给无人风景或纯功能演示强加戏剧反转。
- **多场景、关联提示词或分镜交付**：读取 [shotlist](higgsfield-shotlist-director.md)，沿用素材、编号、状态和工具检查；仅需提示词时交八栏目，分镜任务按其原生 HTML 等契约交付。
- **对白、具体声效、音乐同步或附带音轨**：读取 [audio](higgsfield-audio.md)，先区分原样输出、节奏驱动和表演参考，再选规则；纯音频任务保留原输出。

事件决定阶段，观看需要决定镜头，实际模型与模式限制决定生成片段。规则归属、冲突优先级和去重由统一规范集中维护；图像、资产、工具与模型费用预估按对应流程执行。

### 参数与询问

用户已确认参数优先。**全片、剧情段落、分镜和生成片段都不自动采用30秒或接近30秒的长度。**用户已定总时长及局部预算直接继承；未指定时按内容自然估时。先用 [按内容拆镜与估时](narrative-planning.md#按内容拆镜与估时) 确定每镜的观看任务、起止动作、切点与演出负荷，再映射到模型合法生成片段。不得用增加事件、慢放、重复反应或空等填满单次上限，也不得为了缩短而切掉接触、后果和必要情绪。已有视频编辑继承母片时间线，延伸只预算新增内容。16:9、中文和已定速度继续保留；正式执行核验实际模型与模式参数，已有授权不重复询问。

模型实际能力以包内规格及原文实时核验要求为准；规格过期时保留其在线核验流程。动作需要的总时长超出模型单次上限时，按短片段拆分，并记录连续状态与片段接续关系。未能核验的参数明确标注，不能称为已验证。

### 当前项目：角色资产与写实交付

用户要求角色资产提示词时，必须完整读取并执行 [角色资产交付规范](template-character-asset-delivery.md)，先给资产样本，确认后交资产提示词。仅要求角色视频提示词时，沿用已确认的身份、外观与参考职责；必要时查阅该规范的参考约束，但不输出角色资产提示词。缺少素材时说明缺项，不自动开启资产制作。该规范与原模块默认建议不同时，按本规范执行；其他风格、视频模型及原模块功能仍保留可调用。

- 当前项目视频默认 Seedance 2.5；图片沿用用户确认的 image2.5，默认写实电影质感，不自行推断模型 API 参数。人物资产按规范中的用户格式与阿德莱德案例交付：一段六行提示词，依次写总述、姓名与年龄性别、左侧面部、右侧身体服装、背景与一致性、灯光与质感。
- 默认一张完整角色资产参考图：左侧正面面部特写；右侧无头部的全身正面、侧面、背面，按需在右下方补充服装、配饰或道具的关键细节局部图。提示词直接写“左侧是面部特写”和“左侧：正面面部特写”，不额外强调特写数量。干净浅色背景，左右分区清晰，面部特征与服装细节高度一致。头脸、发型及头部配饰在左侧描述，体型、服装、其他配饰和道具集中在右侧。
- 所有资产图提示词默认写入「画面不出现任何文字、字母、数字、姓名、视图标签、尺寸标注、签名或水印」；角色六行格式并入“背景与一致性”一行，道具、场景与表情参考同样适用。描述中的姓名与视图名称不在图上绘制；用户后续明确指定的品牌文字或场内文字仅按指定范围保留。
- 沿用工作室灯光、电影级光影或柔和电影级边缘光、写实电影质感、8k、高清细节等表达；8k 不代表实际分辨率设置。真实感按需补少量具体肤质与材质细节，不默认堆叠摄影参数、磨损、负面词库，不强行做旧或擅改定稿身份。已有定稿面部不因组板而重新生成；表情参考仅附同源生成备注，由用户单独生成，不引用尚未上传的图。
- 左侧正面定稿为身份主参考；其他面部角度按需单独补充并核对身份，右侧三个身体视图提供体型与服装信息，局部图只补充对应细节，不替代身体视图或增加道具数量。交付前检查身份符合定稿、右侧无头、参考职责、多人身份映射、背景与排版排除项、服装道具及局部细节一致性、阶段状态及适用的 Seedance lint。旧图或失败结果按需另存修复版；未生成或无法查看图片时，构图与真实感标为待视觉验收。

### 当前项目：Seedance 2.5 跨类型视频架构

当前项目采用上述八栏目模板及统一规范，不另建一套 Seedance 写法。单镜头同样保留完整演出，多场景说明时空交接；生成默认 Seedance 2.5 `omni_reference`，编辑和延伸若要求严格保留源时间线则单独核验对应能力。参考标签只绑定真实素材，平台设置独立列出；时间码不承诺逐帧精度。

### 动作设计 → 平台提示词

1. 区分文字、角色身份图、道具图、场景图、分镜、动作/运镜参考视频与对白/声线/环境声参考音频；每份素材写明采用属性、排除项和实际绑定，不以任何参考图充当视频起点。
2. 建立每名角色的八项动作档案，确定可见目标和用户规定的胜负、招式、对白与结尾。
3. 每轮交锋记录发起者、指向、接触结果、回应、位置变化及下一拍条件；延续资源、武器、朝向、损伤和环境变化。
4. 选择适合剧情的原动作骨架，由交锋事件与状态转折确定阶段，按可读性分配镜头和时长，再按模型上限组装连续生成片段；保留 Seedance 整秒时间段和 MiniMax-H3 精确时间码各自格式。
5. 样本确认后默认交付高强度、慢节奏、中间型三套完整方案；用户只要一套时交所选一套。标准/极速是独立速度轴，同时作用于三套，不生成第四套。极速的起手、特写与慢动作规则以动作导演全文为准；微动作、交锋与镜头密度按演出负荷调整，原数量范例不覆盖已确认剧情或强制增加段数。
6. 联合任务逐套覆盖 Model、Camera、Subject、Look、Action 五层（MCSLA），使用已核验的平台词汇与参数。模型与设置列在正文外，其余信息落入八栏目，不再附一套重复 MCSLA。原 200 词等软长度建议仅用于明确要求的短格式；实际提交硬限制按对应模式编译，不删完整母稿的因果与连续状态。
7. 交付前逐项执行 Higgsfield 总指南的 8 条 HARD RULES 与动作导演的数量、空间、资源、因果和边界检查；两套检查都通过才完成联合任务。

### 输出与迭代

联合任务先用用户语言给一行实际读取模块的路由说明。每套动作方案保留“标题、模型/时长/画幅/速度说明、一句设计说明、完整可复制提示词代码块”；Camera 设置和 Motion preset 仅在实际使用相应控件时于正文外列出，正文写具体观察路径。两风格示例不覆盖动作默认三强度。普通视频提示词采用八栏目；分镜、代码动画、纯音频、图像及用户指定 JSON 等专门任务沿用原生交付契约，把同一内容映射进去，不同时输出重复长稿。

默认无字幕、无水印、不加未要求旁白；用户明确要文字或声音时，读取相应文字模板和音频模块。三套方案共享身份、武器数量与能力边界，攻防顺序和结束路径各自设计。失败修正时联用动作诊断与平台 troubleshoot，依据当前素材定位问题，每轮只改动作、镜头或参考素材中的一类变量。
