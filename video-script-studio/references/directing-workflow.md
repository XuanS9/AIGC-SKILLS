# 导演编排与交付

基础资产、场景与视频提示词分阶段写，只响应用户本次要求的范围，先执行 [样本确认流程](sample-approval.md)：完整制作统一规划、共享资产先定稿，再按场景的「补充基础资产 → 场景 → 视频」推进；每阶段先给代表性样本，确认后展开当前阶段。新创作、改写、补镜、修词和单条交付均对变化部分适用，已确认且未变的资产、布局和提示词直接复用，不重复审批。默认文字设定与布局确认后推进，不要求回传全部实图；场景与视频共用 [文字空间布局](spatial-layout.md)，实图未核对不阻止文字定稿。关键设计未定或已知冲突未解时才给受影响部分的条件性预稿，用户明确要求快速预览时才联合交付预稿。实图仅在明确要求或出现偏差时局部诊断。仅视频请求不自动开启资产制作。以下完整稿、角色组板及三强度方案仅用于对应阶段确认后的交付，不因同时要求多类而一次展开全部。

动作、对峙、对白及跨Clip改写同时执行 [动作同步、接缝去重与整场节奏](narrative-planning.md#动作同步接缝去重与整场节奏)：先后/并行共用事件时钟，前尾后首不重演，按整场累计问答等待与行动线缺席；剪辑顺序改变后复核新接缝。


### 全包共用的导演编排

先执行 [导演决策流程](directorial-shot-design.md#导演决策流程)：整场变化与主次 → 观众信息/体验 → 调度 → 比较切镜、镜内交接、停留 → 演出时长 → 删除/合并与反向核对。助手主动选出主方案并按已有授权落地，用户看到关键取舍；不把拍法菜单或每个机位交给用户决定。Clip和生成容量在成片方案之后处理。

规则归属：`narrative-planning.md`管理事件/时序/剪辑与生成，`directorial-shot-design.md`管理注意力和镜头决策，`higgsfield-acting.md`管理可见人物行为，`director-compiler.md`转换为四段式，`production-checks.md`核证据。模板和具体拍法服务这条链，不形成另一套导演流程。

### 资产引用与分镜描述边界

资产文件与项目总表锁定身份、外观、材质、比例、结构和基础场景布局。分镜/视频提示词的【参考素材职责】只引用本镜实际需要的 `@handle` 及职责，不复制资产提示词的基础外观段落。

分镜正文从同版文字布局提取本镜必要的地标关系与路径，不把整个场景重新描述一遍；这些空间锚点不属于禁止重复的外观段落。除此之外只写本段动态变化：持有、交接、进入、离开、伤势、湿污、破损、遗失、空间位置、受力、动作相位和场景后果。固定外观不在视频提示词中重新定义；否则同一角色在资产文件与视频文件中出现两套描述，容易造成身份漂移、模型注意力污染和后续改稿失同步。

提示词是喂给模型的文本，资产文件与 `asset-registry.json` 不会随提示词传给模型。因此【参考素材职责】只放 `@资产` 调用名（平台据此绑定资产图）与本镜新增/衍生内容，禁止写“沿用资产文件/asset-registry 锁定的身份、外观、布局”“以资产图为准”“规划母稿/待绑定”等元描述；这些是我们内部登记用语，不进入提示词正文。


所有视频创作、改写、分镜、动作、编辑与延伸任务，先完整读取 [统一导演编排规范](narrative-planning.md)、[顶级导演分镜方法](directorial-shot-design.md) 与 [导演模板](template-general-director-2-5.md)。完整视频提示词默认按**四段式标准格式**交付：「参考素材职责→一句话概述→具体情节（按时间轴分镜）→全局补充」（详见叙事规划“视频提示词标准交付格式”）；创作或完整改写同时完整读取 [完整演出范本](template-full-performance-example.md)。具体动作与响应保留，全局规则归入【全局补充】写一次，具体情节按时间段写行动与变化；独立分镜各自将本镜现场声内联在触发动作中，台词统一用 `说话人＋状态/语气＋说话动词「原句」`，默认 NO BGM，跨镜音频连续性只列后期剪辑交接，验收留在内部；原生格式按统一规范映射，不重复附长稿。
精简必须保留关键时序绑定：动作同时/先后、触发条件、持续过程及跨段动作相位。能防止停步演表情、等待对方演完或重启动作的局部说明不作冗余删除，按统一规范核对删改前后是否等义。

按 [统一调用与验收总表](production-checks.md#统一调用与验收总表) 记录适用模块、实际读取及正文落点；按内容自动接入以下能力，无需用户点名模块：

- **人物表演**（包括动作、无对白和背景人物）：读取 [acting](higgsfield-acting.md) 人物档案、身体、眼神与验收规则及 [FACS 身体微反应](higgsfield-facs.md#physical-micro-beats--the-body-beyond-the-face)；精细表情、特写按需读取完整 FACS 工作流。细节与状态继承按统一规范执行。
- **非人角色表演**：读取 [非人表演适配](higgsfield-acting.md#非人角色表演适配)，通用行为动机仍用表演模块；不默认使用人类FACS。
- **剧情创作与改写**：读取 [scene-engine](higgsfield-scene-engine.md)，内部检查目标、障碍、策略、反转与价值变化的原定义及适用范围；专门审计时才展示审计报告，不给无人风景或纯功能演示强加戏剧反转。
- **多场景、关联提示词或分镜交付**：读取 [shotlist](higgsfield-shotlist-director.md)，沿用素材、编号、状态和工具检查；仅需提示词时交四段式，分镜任务按其原生 HTML 等契约交付。
- **对白、具体声效、音乐同步或附带音轨**：读取 [audio](higgsfield-audio.md)，先区分原样输出、节奏驱动和表演参考，再选规则；纯音频任务保留原输出。

事件决定阶段，导演意图与观看任务决定镜头，实际模型与模式限制决定生成片段。先判断观众此刻应先看到什么、后知道什么，以及镜头要表达的情绪、关系、尺度、信息差或主动权转移；再选择景别、机位、运镜和切点。不规定每个 Clip 的分镜数量，也不设单镜3秒上限或默认镜长；按实际叙事、动作、对白、表演和可读性决定短镜、长镜或镜内交接，每个 Clip 总时长仍≤30秒。不得因为片段接近30秒就均分镜头，不得为“丰富”而重复反应特写；长镜必须有内部调度、关系动作、空间揭示或背景危险推进。规则归属、冲突优先级和去重由统一规范集中维护；图像、资产、工具与模型费用预估按对应流程执行。

正式剧情先落实场景的核心重点、必要支撑与连接，再执行 [多景别与多角度覆盖](directorial-shot-design.md#剧情驱动的多景别与多角度覆盖)：从必要的环境/关系、行动、物件、接触、反应与决定选择观察层次，不把固定广角空间测试沿用为默认拍法。表情、手部与特殊道具特写须交付剧情信息，保留持有链、视线和动作相位；不机械加镜、不擅添资产或情节。**大幅度物理空间转移另按[大幅度空间转移：必须拆镜或用甩镜头过桥](directorial-shot-design.md#大幅度空间转移必须拆镜或用甩镜头过桥)编排**，不把跨地点移动压成一个清晰画面。当前景别只写可见细节，用户指定长镜/固定机位或纯氛围形式继续保留。

先执行 [多线叙事与交叉剪辑](narrative-planning.md#多线叙事与交叉剪辑)：叙事单元可跨原场号和多个Clip，场景批次不决定成片顺序；先定各线露出与回切，再按可控性映射生成。约30秒是次级效率目标，不能以凑段为由延迟必要行动线。

生成交付必须完成 [合并与短段例外验收](narrative-planning.md#生成分组与短段例外验收)：尽量接近30秒、先评估兼容合并，记录不能合并的具体理由；改写压缩时长后也要重做分组。表演描写按 [证据验收](higgsfield-acting.md#表演证据验收) 查到具体镜头，不只报告已读模块。

### 参数与询问

用户已定成片总时长及局部预算直接继承，但每个 Clip／生成片段总时长不得超过30秒；模型单次上限更短时取更短值。超量内容由助手直接按[压缩或顺延规则](narrative-planning.md#单个clip的30秒硬上限与超量处理)处理，放不下的完整动作／对白单元传到下一个 Clip，不延长单条。在该上限内可用兼容的连续多阶段内容编组。先用 [按内容拆镜与估时](narrative-planning.md#按内容拆镜与估时) 确定每镜的观看任务、起止动作、切点与演出负荷，再映射到模型合法生成片段。靠真实连续内容填满，不用增加无关事件、慢放、重复反应或空等注水，也不为缩短而切掉接触、后果和必要情绪。已有视频编辑继承母片时间线，延伸只预算新增内容。16:9、中文和已定速度继续保留；正式执行核验实际模型与模式参数，已有授权不重复询问。

模型实际能力以包内规格及原文实时核验要求为准；规格过期时保留其在线核验流程。动作所需时长超出30秒或更短的模型单次上限时，先合理压缩；不能压缩的内容顺延拆分，并记录连续状态与片段接续关系。未能核验的参数明确标注，不能称为已验证。

### 当前项目：角色资产与写实交付

用户要求角色资产提示词时，必须完整读取并执行 [角色资产交付规范](template-character-asset-delivery.md)，先给资产样本，确认后交资产提示词。仅要求角色视频提示词时，沿用已确认的身份、外观与参考职责；必要时查阅该规范的参考约束，但不输出角色资产提示词。缺少素材时说明缺项，不自动开启资产制作。该规范与原模块默认建议不同时，按本规范执行；其他风格、视频模型及原模块功能仍保留可调用。

- 视频默认 Seedance 2.5；图片模型与媒介继承用户/项目已确认设置，未指定时按入口推荐，不把历史项目的image2.5或写实方向当全局默认，不自行推断模型API参数。人物资产按规范中的用户格式与阿德莱德案例交付：一段六行提示词，依次写总述、姓名与年龄性别、面部特写、三格全身与服装、背景及图底条、灯光与质感。
- 默认全图共4格：唯一清晰面部特写＋正面/90°侧面/背面完整全身；全身格保留头部、不刻画五官，头顶至鞋全部入画，明确头身比、端正站立、双手空着。穿戴配饰保留，独立道具由P类提供；材料与鞋袜细节并入对应格，不另加特写格。
- 角色图片图底只保留非文字波形，全图无文字标签，不附音色描述；换装复用身份与版式。道具、场景与表情图继续执行各自无文字规则。
- 画风、材质与光照完整继承角色规范的对应媒介分支，是什么风格就用什么风格；不默认堆质量词、摄影参数、磨损或负面词库。组板与修复保留定稿面部，表情仅另附同源生成备注。
- 交付前核四格总数、唯一清晰脸、完整头身与鞋袜、空手站姿、服装一致性、图底非文字波形与全图无字。全身格多脸时局部修面部并保留头型，缺头脚时补对应格，另存版本。参考板的背景、面部处理、排版与波形不进入成片；未生成或未看图不标视觉通过。

### 当前项目：Seedance 2.5 跨类型视频架构

当前项目采用上述四段式标准格式及统一规范，不另建一套 Seedance 写法。单镜头同样保留完整演出，多场景说明时空交接；生成默认 Seedance 2.5 `omni_reference`，编辑和延伸若要求严格保留源时间线则单独核验对应能力。参考标签只绑定真实素材，平台设置独立列出；时间码不承诺逐帧精度。

### 动作设计 → 平台提示词

1. 区分文字、角色身份图、道具图、场景图、分镜、动作/运镜参考视频与对白/声线/环境声参考音频；每份素材写明采用属性、排除项和实际绑定，不以任何参考图充当视频起点。
2. 建立每名角色的八项动作档案，确定可见目标和用户规定的胜负、招式、对白与结尾。
3. 每轮交锋记录发起者、指向、接触结果、回应、位置变化及下一拍条件；延续资源、武器、朝向、损伤和环境变化。
4. 选择适合剧情的原动作骨架，由交锋事件与状态转折确定阶段，按可读性分配镜头和时长，再按模型上限组装连续生成片段；保留 Seedance 整秒时间段和 MiniMax-H3 精确时间码各自格式。
5. 样本确认后默认交付高强度、慢节奏、中间型三套完整方案；用户只要一套时交所选一套。标准/极速是独立速度轴，同时作用于三套，不生成第四套。极速的起手、特写与慢动作规则以动作导演全文为准；微动作、交锋与镜头密度按演出负荷调整，原数量范例不覆盖已确认剧情或强制增加段数。
6. 联合任务逐套覆盖 Model、Camera、Subject、Look、Action 五层（MCSLA），使用已核验的平台词汇与参数。模型与设置列在正文外，其余信息落入四段式，不再附一套重复 MCSLA。原 200 词等软长度建议仅用于明确要求的短格式；实际提交硬限制按对应模式编译，不删完整母稿的因果与连续状态。
7. 交付前逐项执行 Higgsfield 总指南的 8 条 HARD RULES 与动作导演的数量、空间、资源、因果和边界检查；两套检查都通过才完成联合任务。

### 输出与迭代

每次修改后执行 [修改后标准复查闭环](production-checks.md#修改后标准复查闭环)：读回最终落盘稿，核完整改动条目与受影响接缝/依赖，修复后重跑适用检查；不沿用旧版通过结论，检查记录留复制块外。

联合任务先用用户语言给一行实际读取模块的路由说明。每套动作方案保留“标题、模型/时长/画幅/速度说明、一句设计说明、完整可复制提示词代码块”；Camera 设置和 Motion preset 仅在实际使用相应控件时于正文外列出，正文写具体观察路径。两风格示例不覆盖动作默认三强度。普通视频提示词采用四段式；分镜、代码动画、纯音频、图像及用户指定 JSON 等专门任务沿用原生交付契约，把同一内容映射进去，不同时输出重复长稿。

默认无字幕、无水印、不加未要求旁白；用户明确要文字或声音时，读取相应文字模板和音频模块。三套方案共享身份、武器数量与能力边界，攻防顺序和结束路径各自设计。失败修正时联用动作诊断与平台 troubleshoot，依据当前素材定位问题，每轮只改动作、镜头或参考素材中的一类变量。
