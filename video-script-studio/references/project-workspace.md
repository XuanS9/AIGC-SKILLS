# 项目工作区：跨会话继承剧本、资产与参数

让已确认的剧本、资产和参数落到用户项目目录的固定文件里，新会话读回后直接继续创作或生成提示词，不重述设定。本机制与 [项目资产总表](asset-registry.md) 配合：`project.md` 管剧本、参数与进度，`asset-registry.json` 管资产身份与场景布局。

## 文件夹结构

工作区建在用户项目目录（不是 skill 安装目录）：

```
<项目名>/
  project.md            # 项目圣经：参数、故事、人物、对白、场景与 Clip 序列、批次进度
  asset-registry.json   # 资产总表 + 场景布局锚点（见 asset-registry.md）
  prompts/              # 已确认交付的提示词存档，按场景/Clip 命名
    scene01-clip01.txt
  assets/               # 可选：实际生成的资产图/片段路径，或在 registry 的 file 字段登记
```

## 会话开始：读取继承

1. 用户指向工作区（给出路径，或工作区在当前目录）后，先完整读取 `project.md` 与 `asset-registry.json`，继承全部已确认的参数、故事、结局、人物、对白、资产名称、场景布局与批次进度。
2. 无法访问项目目录，或用户未指向工作区时，按普通新项目流程处理，并说明：需要用户提供工作区路径才能继承；不虚报已记住上次项目。
3. `project.md` 与 `asset-registry.json` 冲突时，以两者都明确记录且时间更新的为准；无法确定的条目标待核对，不自行合并或改写已确认结局与身份。
4. 继承不等于本次样本已确认：已确认的设定、参数和资产可直接复用，但新写、改写、补镜的提示词仍按 [样本确认流程](sample-approval.md) 先给本次样本。

## 交付后：更新写回

每次用户确认新的参数、剧情、结局、对白、资产或批次后，更新对应小节并刷新顶部「最后更新」与「当前进度」：

- 新确认的参数、故事或结局 → 更新对应小节；已确认结局不随后续会话随意改写，确需变更时记入变更记录。
- 新增或改名资产 → 同步 `asset-registry.json`（handle、file、status、layout）与 `project.md` 的人物/道具/场景小节。
- 交付一个批次的提示词 → 在「场景与 Clip 序列」更新状态，把可复制提示词存入 `prompts/`。
- 只处理本地文本、无法写盘时，在交付中附更新后的 `project.md` 与总表全文，说明需用户保存；不声称已落盘。

## project.md 模板

```markdown
# 项目圣经：<项目名>

> 与 asset-registry.json 同置于项目目录，是跨会话继承的剧本与参数来源。
> 新会话先读本文件与 asset-registry.json 再继续；用户确认新内容后更新对应小节。

最后更新：<日期>｜当前进度：<一句话，如“场景1的3个Clip已交付，场景2待样本确认”>

## 项目参数
- 平台与模型：<如 Seedance 2.5 / omni_reference>
- 生成片段默认时长：<如 约30秒（向模型单次上限凑）>
- 画幅：<如 16:9>　语言：<如 中文>　速度轴：<标准/极速>
- 动作强度默认：<高强度/中间型/慢节奏，或三套全交>
- 视觉参考电影：<片名 + 借用的光色/尺度/摄影语言，不搬角色地标>
- 画质基调：<如 电影级写实质感，落到光比/材质/景深/空气透视>
- 声音默认：<如 NO BGM，只现场声>

## 故事
- 梗概：<一段>
- 已确认结局：<明确结局>
- 主题/基调：<可选>

## 人物设定
- <角色名>（@C_handle）：<身份、年龄、性格、能力边界与关系；外观细节以资产提示词为准>

## 关键道具与生物
- <名>（@P_/@B_handle）：<剧情功能、归属、数量、约束>

## 场景与空间
- <场景名>（@S_handle）：<剧情作用；空间布局锚点以 asset-registry 的 layout 为准>

## 对白（如有）
- <场景/Clip>｜<角色>：「<台词>」（已确认/待定）

## 场景与 Clip 序列
| 批次/场景 | Clip | 剧情内容 | 时长 | 状态 |
|---|---|---|---|---|
| 场景1 | Clip1 | <一句> | ~30s | 待样本/待确认/已交付 |

## 批次进度
- 已确认并交付：<列表或“无”>
- 待样本确认：<列表或“无”>
- 待办：<列表或“无”>

## 变更记录
- <日期>：<改了什么、为何改>
```

外观与结构细节的唯一权威是资产提示词与 `asset-registry.json`；`project.md` 记剧情人设、关系、参数与进度，两者指向同一套 `@handle`，不重复冗长外观描述、不另起名称。
