# 项目工作区：跨会话继承剧本、资产与参数

让已确认的剧本、资产和参数落到用户项目目录的固定文件里，新会话读回后直接继续创作或生成提示词，不重述设定。本机制与 [项目资产总表](asset-registry.md) 配合：`project.md` 管剧本、参数、阶段进度与依赖交接，`asset-registry.json` 管资产身份、场景布局及对应文件版本的核对记录。默认统一规划、共享资产先定稿，再按场景的「补充基础资产 → 场景 → 视频」推进；明确要求快速预览时才启用联合预稿。

## 文件夹结构

工作区建在用户项目目录（不是 skill 安装目录）：

```
<项目名>/
  project.md            # 项目圣经：参数、剧情、Clip 序列、阶段进度、依赖与交接
  asset-registry.json   # 资产总表 + 布局 + 提示词/实图核对记录
  prompts/              # 提示词存档；版本与确认状态在 project.md 中记录
    basic-assets/       # 共享及补充 C/B/P 提示词
    scenes/             # S 场景提示词
    video/              # 按批-序命名，如 clip-1-1-v01.txt
  assets/               # 可选：实际生成的资产图/片段路径，或在 registry 的 file 字段登记
```

美术设定沿用项目实际文件组织，`project.md`记录其路径与版本；可为已有美术文件，也可为项目记录内明确的美术章节。它负责具体风格、参考职责、天气光色、材料和陈设；通用Skill负责将设定转译为提示词。

用户已指定四个汇总提示词文件或其他结构时直接继承，不强制改用上面的子目录。复制用文件只放必要标题、Clip/场景图号及提示词；状态、备注与验证留在本项目记录和总表。

## 会话开始：读取继承

1. 用户指向工作区（给出路径，或工作区在当前目录）后，先完整读取 `project.md`、`asset-registry.json`及记录指向的当前美术设定，继承全部已确认的参数、故事、结局、人物、对白、资产名称、场景布局、交付模式、当前批次/阶段及依赖状态。按真实交接点继续：待样本确认则停等确认，文字设定与布局已确认且未变则复用并推进；默认不等待用户回传实图，仅在用户明确要求严格验收或已知偏差待解决时请求相关结果。不把提示词已交付当作图片已通过。
2. 无法访问项目目录，或用户未指向工作区时，按普通新项目流程处理，并说明：需要用户提供工作区路径才能继承；不虚报已记住上次项目。
3. `project.md` 与 `asset-registry.json` 冲突时，以两者都明确记录且时间更新的为准；无法确定的条目标待核对，不自行合并或改写已确认结局与身份。
4. 已确认且未变的设定、资产、布局和提示词直接复用，不重复审批；新写、改写、补镜仍按 [样本确认流程](sample-approval.md) 给当前阶段变化部分的样本。已有当前版本的样本确认记录时直接展开其范围，不因跨会话再确认一次。
5. 读回场景图号、直接源图号、复用关系及每个Clip的具体图号引用；按 [总表图号规范](asset-registry.md#场景图编号与clip双向映射) 保持编号稳定，不把S图号当作视频批次或平台槽位。
6. 旧项目缺少阶段/核对字段时保持原路径、命名与交付，不强制迁移文件；按可查证记录补充进度。旧流程中的“待实图”若没有用户明确要求或已知冲突，不继续作为默认文字交付阻塞；说明改用文字布局路径，保留实图未核对及真实绑定状态，不推断视觉通过。

## 交付后：更新写回

每次用户确认新内容、交付当前阶段提示词或取得实图检查证据后，更新对应小节并刷新顶部「最后更新」与「当前进度」：

- 新确认的参数、故事或结局 → 更新对应小节；已确认结局不随后续会话随意改写，确需变更时记入变更记录。
- 美术确认或变更 → 先更新项目美术设定，将参考职责、受光、天气、色彩、材料与陈设写成可见特征；`project.md`和总表登记来源路径及版本，复核受影响提示词。
- 新增或改名资产 → 同步 `asset-registry.json`（handle、file、status、layout 及核对记录）与 `project.md` 的人物/道具/场景小节。
- 交付当前阶段提示词 → 更新阶段进度、样本版本、确认范围/依据、提示词路径；视频另更新「场景与 Clip 序列」。样本、条件性预稿和定稿分开标记，提示词存入 `prompts/`，不覆盖已确认版本而不留变更记录。
- 场景图交付、换源或合并 → 在总表view_plan维护image_id/source_image_id/实际文件及复用状态，视频Clip维护scene_image_references；同步场景与视频标题，核对双向映射。原剧本场号仅在本文件/总表作溯源；备注与检查不回填复制用文件。
- 文字布局确认/修改 → 将基准视点、地标位置、连接、高差、通道等写入总表 `layout`，记录版本；场景与视频引用同版底稿，细则见 [文字空间布局](spatial-layout.md)。不另建强制地图文件。
- 按需接收实图并检查 → 记录实际文件版本、检查结果/差异与证据，更新总表的 `visual_review`；发现冲突时标相关设计待复核，经用户确认改变布局后才更新 `layout` 的依据、版本与文字确认状态。文件存在只代表素材具备，不自动标视觉通过或已绑定。
- 上游文件/布局变更 → 列受影响的下游 Clip/阶段为待复核；未受影响内容保留确认，复核无影响则恢复原状态，有影响才修样本。
- 视频场末交接 → 在本文件的「连续性快照与未解线头」记录场末位置、身体朝向/视线、左右手持物、动作相位/动量、可见情绪与气息；引用对应 Clip 提示词版本与末段原句，避免第二套改写。伤势、湿污、破损、场景变化及道具遗留只记持续项，后续回收时记关闭位置。跳时/转场写明已确认依据，不把不连续时空强行接成同一状态。详见 [导演编译](director-compiler.md)。
- 控制参考/返工 → 仍在对应 Clip 的依赖与变更记录中登记源文件、版本、作用时段、待回填依赖及实际绑定；不增设另一资产索引、独立状态账或强制控制图阶段。方法见 [导演控制与返工](director-control-retake.md)。
- 阶段交接 → 记录当前等待项（样本确认/布局补充/绑定/继续下一批，按需实图诊断或修图）与下一步，不用单个“完成”同时表示文字、图像和视频完成。
- 只处理本地文本、无法写盘时，在交付中附更新后的 `project.md` 与总表全文，说明需用户保存；不声称已落盘。

## 调用、分组与验收的现有记录位置

视频任务将 [统一调用与验收总表](production-checks.md#统一调用与验收总表) 的适用项、实际读取、正文落点、四态结果与复验信息写入本文件现有检查小节；无工作区时块外交接，不新增强制审计目录。表演采用已有模块，不另建一套表情规范。

生成分组在本文件已有分配表或总表video_delivery中记录：生成片段/版本、覆盖镜头/既有Clip区间、生成片内时间→成片位置、生成与净使用时长、合并候选及短段理由。每个 Clip 总时长≤30秒，模型上限更短时取更短值；上限内尽量合并兼容内容，超量按[压缩或顺延规则](narrative-planning.md#单个clip的30秒硬上限与超量处理)移到下一条，并同步分配表、片内从0开始的时间轴、引用时段与接缝。已覆盖的旧短稿不再列为独立待生成。模板字段可按任务省略，不改原schema_version或资产必填字段，不追认旧项目尚未执行的检查。

三个层级各自记录通过/失败/待核验/不适用；旧证据保留版本，改写后只复核受影响范围及新接缝。用户确认设计、文字通过、素材绑定和实际生成验收分别记录。

```markdown

> 新会话先读本文件与 asset-registry.json 再继续；用户确认新内容后更新对应小节。

- 当前批次与阶段：<统一规划/共享基础资产/第N批补充基础资产/场景/视频>

- 阻塞与预稿假设：<关键设计未定或已知冲突；缺素材/未绑定仅阻塞提交，不自动阻塞文字定稿>
- 下一步：<文字设定/布局确认后推进到何阶段；严格模式或异常诊断另记等待项>

## 项目参数
- 平台与模型：<如 Seedance 2.5 / omni_reference>
```
