# 资产设计依据：从故事推导外观

本页是角色 C、生物/植物 B、道具 P、场景 S 外观推导的唯一负责模块。格式、版式和画法仍由各资产模板负责；本页只规定**外观从哪里来、怎样核对**。是否建立资产先按[独立视频提示词门槛](asset-registry.md#资产建立门槛按独立视频提示词计数)判断；确定需新建／改写资产后再执行本页，不把依据卡当作所有一次性对象都要建图的理由。

## 剧本到设计的最小闭环

**先理解故事，再做美术取舍，最后写图片提示词；不是把人物名、性格词和“高清”拼成一段。**助手内部完成下列步骤，复用现有依据卡、总表和 `project.md`，不让用户另填问卷或审批一份设计大表。仅处理本次需新建/改写的范围；已有且未变的确认设计直接沿用。

1. **读取与分流。**读用户提供的剧本及相关世界观、人物和美术资料，记录实际版本与范围；没有某类资料就用已有事实，不把每份文件都变成前置要求。将信息分成：**明确设定**（原文与已确认选择）、**合理推导**（基于什么、为什么这样设计）、**待核问题**（相互冲突或缺失且影响身份、剧情、结构）。未读取的附件不冒称看过；外部参考不能覆盖已确认世界观。
2. **先抽剧情用途。**按场次找出谁会被辨认、什么会被握持/打开/损坏、从哪里通行、何时换装或受伤，再按资产门槛筛共享对象。剧情需要先于装饰；“角色”“道具”“场景”名单不等于需求已提取完整。
3. **设计而非照抄资料。**依据卡中的身份、处境、性格及世界条件，按下节形成可见设计与理由；把关键选择落实到现有视图、部位与功能结构。非关键且未明确的外观可提出一个合理候选，随本阶段样本确认，不逐个询问颜色和纽扣。关键矛盾集中提出，不静默选一边，也不把未定设计写成事实。
4. **先样本、再展开。**当前资产样本外用几句说明主要依据、推导取舍和需要确认的点；复制块只写具体画面。已确认样本沿原流程展开，既有设计不重复审；不额外增加风格板、色卡、全项目实图回传或批准关卡。
5. **核正文，再核结果。**按本页双向核对确认“故事需求→设计→提示词”没有断链；有实际图片时再看结构、身份和关键细节是否真的实现。只有文字时交提示词与生成交接，不声称已出图；调用生图工具仍以实际能力和授权为准。缺陷回到对应资产局部修复，不把上游外观问题留给视频重设计。

首次从剧本做资产，或诊断“描述齐但不像这个人物/世界”时，读[剧本驱动资产小样](template-story-driven-assets.md)，参考其依据与正文的对应关系，不复制案例外观。

## 1. 依据卡（内部，写资产前做）

先读剧本正文、世界观设定、人物圣经、美术设定和 `project.md`，为每个资产填一张依据卡。依据卡记入项目的资产总表条目（`design_basis` 字段）或 `project.md` 对应小节，不进入可复制提示词正文。

| 项 | 写什么 | 角色 C | 生物/植物 B | 道具 P | 场景 S |
|---|---|---|---|---|---|
| 世界与时代 | 地理、气候、技术和材料水平、经济与社会结构 | 必填 | 必填 | 必填 | 必填 |
| 身份与处境 | 职业、阶层、财富、生存压力、在故事里的位置 | 必填 | 生态位、与人的关系 | 归属者、用途、获得方式 | 场所用途、谁建造、谁使用 |
| 经历留下的痕迹 | 旧伤、劳损体态、冻裂/晒伤、修补、磨耗；只写已发生的 | 必填 | 必填 | 必填 | 必填 |
| 来源与制作 | 自制、修补、继承、交易、制式配发；对应的工艺和痕迹 | 服装配饰 | — | 必填 | 建材和施工方式 |
| 剧情用到的可见特征 | 剧本里会被看见、被使用、被破坏的部件；左右侧、数量、位置 | 必填 | 必填 | 必填 | 地标、通道、遮挡、高差 |
| 性格与关系的外化 | 体态、穿法、整洁程度、与他人的视觉对照 | 必填 | 行为倾向 | — | — |
| 状态版本 | 剧情中反复出现的重大外观变化（受伤、湿污、破损、换装、年龄段） | 必填 | 必填 | 必填 | 必填 |

**每项写明来源**：剧本场次号、设定文件名与小节。来源格式 `来源：剧本 5f` / `来源：11_人物圣经 §Runa 优点与局限`。原文没有写、由助手推导的内容标 `推导`，随样本请用户确认；不把推导写成已确认事实，也不为填满表格虚构经历。确实不适用的项写“不适用＋原因”。

### 从依据到可见设计

对**剧情必需特征和显著美术选择**补一条简短链：

`原文/已确认依据或推导来源 → 设计选择与理由 → 可见部位/结构 → 正文视图或状态落点 → 使用与核对方法`

链写入原依据卡的说明或 `project.md`，不增加必填 JSON 字段或第二份表；无需为每块普通布料建记录。`script_features` 仍只记录剧情特征及承担位置，不能把推导写成原文。脸型、配色等原文未规定但需要成图的选择可标“设计候选”，确认范围记原样本记录。缺项、未知和冲突不等于“不适用”。

| 对象 | 推导路径 | 避免的偷懒写法 |
|---|---|---|
| C 角色 | 身份/工作决定服装形制与活动余量；资源和取得方式决定材料/工艺；已发生经历决定痕迹；性格通过有依据的穿着、整理、保养与取舍体现；同场人物比较角色定位 | “贫穷所以全身脏破”“反派所以刀疤黑衣”“善良所以漂亮”；按性格改肤色、脸型或永久表情；把职业名称当完整造型 |
| B 生物/植物 | 世界生态、行动方式和已定能力决定比例、支撑/可动结构及适用表面；斑纹与辨识细节遵守同一物种/个体设计 | 为了动作临时多出肢体；把人类性格直接画成人脸；把虚构能力假称生物学事实 |
| P 道具 | 谁拥有/制作/修理、当地材料与技术、如何获得和实际操作，决定尺寸、部件、接合、开启及握持位置；手工或制式有不同可见痕迹 | “神秘古董/高科技设备”但没有机构；有盖无连接、有扣无扣座；为了好看挡住使用部位 |
| S 场景 | 气候/资源与文化技术决定建筑形制、材料和施工；用途与使用者决定出入口、采光、通道和维护痕迹；剧情路线约束连接与尺度 | 只写“奇幻城堡/贫民屋”；把不同文化建筑随机混搭；装饰堵住必经通道；为画出职业而往纯环境里加人和道具 |

这些是取舍方法，不是性格到外貌的固定公式。角色设定板保留中性展示，不把当场恐惧或愤怒冻结为身份。世界观的魔法/超常结构按已确认规则设计，不擅自套现实工艺否定它；题材也不能自动决定真人或动画媒介。

**功能结构先推演。**只针对剧情会用到的动作，核一次“怎样用、哪里动、谁接触、空间够不够”：袖口是否能卷起、匣盖是否有转轴、握持处能否容手、门洞与人物/携物尺度是否相容。数值有原文用原文，新增尺寸是设计候选，不伪称实测。资产图呈现静态结构和已定起态；动作过程进视频，重大状态变化按 §4；中性图不能预画未来伤痕，也不能为展示功能把多种状态混成同一物体。需展示结构时沿既有视图分配，不自动加图。

## 造型辨识度与身材设计

**符合故事是底线，鲜明、有吸引力、能被记住是设计目标；中性展示不等于造型平庸。**不以堆质量词或“全部合理”代替美术取舍。剧本未规定之处，允许主动提出相容的原创比例、轮廓、形体节奏和配色方案，标为设计候选并随现有样本确认；理由可以是视觉主次、人物对照或审美选择，不必伪造一段经历来解释每个造型。明确设定、已确认身份/体型/媒介/布局仍是边界，不能为醒目擅改。

### 先大形，后细节

1. **先身体或主体体量。**角色不能只写身高和“匀称/结实”。给出骨架与整体体量、肩胯关系、躯干与腿长比例、必要的肌肉/脂肪分布及稳定体态；保留符合年龄和已定媒介的自然或风格化尺度。职业、生活条件是设计约束而非体型定律，不套“穷必瘦、富必胖、英雄倒三角”，不将性格或道德绑定脸型/肤色/体重。暂时疲惫和当前表演不冻结为身体身份。服装顺着身体的实际厚度、活动余量和重力设计，不能只靠宽袍遮住未设计的身材。
2. **以大轮廓建立差异。**角色看头发轮廓、肩颈、衣长、袖形和裤裙体量；生物看头躯四肢/尾等体量组合；道具看外形、握持与主要机构；场景看建筑/地形轮廓、体块、空间留白及已有地标关系。方短与窄长、厚薄与疏密等可作组合，不机械给每个对象贴一个几何图形。
3. **选主记忆点，再安排支撑。**关键角色/生物、核心道具与场景应能用简短可见描述说出最值得记住的设计；通常一个主记忆点加少量支撑即可，但不是数量配额。可以是特殊领肩关系、稳定色块、结构转折或标志空间，不强制伤疤、异色眼、不对称、披风或巨大配饰。配角和普通物件保留适量特征，为主视觉让位；不让所有资产同时抢戏。
4. **色块和材质服务主次。**远处先读体量/轮廓，中距离读主色块与标志形体，近处再读接缝、磨耗与工艺；不是每个对象都靠全尺度辨认。换成灰度或相近光照时，关键对象不应只靠颜色名字区分。保持项目画法与材料体系，允许身份/阵营的有意对照；不为抢眼给所有对象加同一高饱和点缀。
5. **识别必须能延续到运动。**标志形体的部位、尺度、左右与连接在原视图内写清，换角度仍能还原同一设计；它不能无意遮住剧情需辨识的脸部、妨碍必要关节活动、挡住握持/开合或堵塞通路。已定面具、仪式服装、特殊生物结构等按实际叙事职责处理，不以通用实用性抹掉有意设计。全身格仍按原裁切，头发记忆点放面部格，不为剪影检查新增头部或额外组板。视频引用已定外观，不在各Clip再次发明特点。

样本块外可用一两句说明“主要轮廓＋记忆点＋与同场对象的差别”；身体和标志形体必须实际进入资产复制正文。已有且未变设计不自动重做，不新增配套表、色卡或审批。示范见[两角色与道具/场景小样](template-story-driven-assets.md)。

### 辨识度复查

先人工读回正文，确认写的是可见形体而非“独特、惊艳、高辨识度”；有图片后再做以下适用检查。不要求另生成黑剪影图或上传全套素材。

| 看什么 | 核对方式 | 不足时优先修改 |
|---|---|---|
| 缩略图与大轮廓 | 缩小/忽略纹理，主轮廓、体量和大色块是否仍分明；角色参考按实际裁切判断 | 身体比例、服装长度与体块，不先加花纹 |
| 同场对照 | 暂去名字，关键对象能否凭设计组合区分；普通物件是否喧宾夺主 | 差异轴与视觉主次，不强行全员怪异 |
| 记忆点与审美主次 | 能否说出一个明确主特征，其他细节是否支撑它；留白、疏密和比例是否协调 | 合并竞争细节、强化主形，允许克制风格 |
| 跨视图与动态适配 | 特征在不同视角的连接、左右、数量是否一致，能否支持剧情动作 | 结构与视图描述，不靠标识文字或特效遮盖 |

文字通过只表示设计方案可定位；未生成图不得声称剪影或吸引力已验证。观众是否喜欢不能由模板或lint保证，必要时通过样片反馈调整，不伪造评分或保证爆款。

## 2. 从依据卡编译到提示词

- **可见化。**依据卡里的处境和经历，只有能被看见的部分进入提示词：冻裂指节、袖口反复缝补、按工钱买得起的材料、制式装备的统一磨损。抽象说法（“贫穷”“坚韧”“有故事感”）必须换成可见的材料、痕迹或体态。
- **剧情特征一一落点。**依据卡“剧情用到的可见特征”每一条都要在对应格或对应视图里出现，并保持左右、数量和位置；如果该特征只在状态版本中出现，写进状态衍生图计划。
- **世界内一致。**同一势力、阶层、地区的角色和场景共用材料体系与工艺水平；同一世界不混入不属于它的技术、面料或建筑构件。
- **基础图是故事开始时的状态。**基础图画该资产在剧情起点的样子（含已有旧伤和磨耗），不画尚未发生的伤害；剧情中途才出现的变化进入状态衍生图。干净浅色背景、无头全身格等版式规则不变。
- **风格先落实到资产。**按[资产图先定画风与细节](higgsfield-style.md#资产图先定画风与细节)，把同版项目媒介/画法、配色及材质表现写进 C/B/P/S 正文，再把本资产的固有色、关键结构与可见细节落到对应部位和视图，不能留给视频重新设计。外部电影/剧集只作为美术设定的拆解来源，复制正文不写片名或剧名，也不写“某作品质感”这类整体锚定；参考作品的角色、服装、徽记和场景不搬入。
- **不确定先问。**关键外观在剧本和设定里互相矛盾，或缺失且会影响剧情可读性时，列出冲突和候选方案，随样本请用户选择，不静默选一边。

## 3. 双向核对（交付前）

1. **剧本 → 资产或视频。**先按[资产门槛](asset-registry.md#资产建立门槛按独立视频提示词计数)区分共享与单次对象，再逐场核角色、生物、道具、场景的可见外观需求：共享需求对到资产正文／状态图，单次未建资产者对到视频正文。不能因剧情特征重要就绕过计数强建图，也不能漏掉单次对象所需描写。
2. **资产 → 剧本。**资产正文里每个显著特征（伤疤、饰物、特殊结构、地标）都能在依据卡里找到来源；找不到来源的删掉或标为推导候选。
3. **跨资产对照。**同框资产的媒介、画法与材质表现是否属于同一项目；同一场景角色在阶层、财富和材料上的差异是否可读，而不是被统一配色抹平；角色体型与场景通道、门洞、家具尺度是否相容。
4. **造型与辨识度。**按[造型辨识度与身材设计](#造型辨识度与身材设计)核身体/主体体量、大轮廓、主记忆点和同场对照，重要资产不能只有泛称或零碎装饰；文字设计与实图识别分开记录。
5. **可用性与状态。**只看资产正文，还能找到剧情必需的可动/接触结构、可通行空间和其基准状态吗？各视图的数量、左右、连接一致吗？必要细节在指定视图大小下可读吗？缺失回设计/视图分配，不能只在依据说明里补一句；有字面词也不证明功能成立。
6. **规则更新后复查。**Skill 的资产版式或项目视觉总纲变化后，已交付但未定稿的资产按新规则复查；已定稿且用户确认保留的资产只记录差异，不自动重写。

核对结果并入现有项目检查：`资产｜来源与设计理由｜正文/视图落点｜基准/后续状态｜剧情使用检查｜缺口`。自动计数不能代替这些判断。判断不适用须有理由，缺资料记待核验。

**实图核对与修复。**看图后分别核人物/世界契合、剧情特征与功能结构、跨视图一致、关键细节可辨、跨资产相容；引用实际部位或图中区域，不能仅说“好看/高质”。发现已知偏差先修相关图片或经确认更新设计，并复核受影响下游；未看图只记文字通过和“实图未核对”，不要求为文字推进补传所有图片。

### 人工回归情境

| 情境 | 应有处理 | 失败信号 |
|---|---|---|
| 拮据但爱惜物件的劳动者 | 区分经济条件与保养习惯；材料/剪裁可据职业推导，修补程度另标候选 | 统一满身污泥破洞，或擅加伤疤 |
| 场景使用本地木石、低技术工艺 | 结构与连接遵守设定，补明确用途、入口和通路 | 只写“古风”，却无依据加入玻璃幕墙或电气设备 |
| 剧情要求打开道具、携物过门 | 核开启结构、接触部位、体量与通道；具体落到资产正文 | 只有“可以打开/可以通过”的说明，没有结构 |
| 第二场才受伤或衣物破损 | 基础图保留起点完好，变化归对应状态/视频 | 基础图提前带新伤，或后续换镜自动消失 |
| 原文与人物资料在身份/年代上冲突 | 标出各来源，先解关键冲突；其他已定部分照常推进 | 静默合并为两种身份或编造第三种设定 |
| 原文未写脸型与服装颜色 | 提出与世界和角色相容的设计候选，随当前样本确认 | 声称原文规定该脸型，或每个纽扣都单独问用户 |
| 人物、道具、场景分别设计 | 比较媒介、工艺、尺度和功能接口；允许有依据的身份差异 | 每张单看漂亮，同框却像三个时代/媒介 |
| 两角色服装细节不同但身材和衣长一样 | 先比较体量、躯腿/肩胯比例和主要轮廓，按确认范围设计差异 | 只增加不同项链或换颜色，仍一眼分不清 |
| 中性参考板看起来平庸 | 保留站姿/背景规范，强化主体形体、主次和标志造型 | 用战斗姿势、浓雾或炫光代替造型设计 |
| 装饰过多影响识别与活动 | 删并竞争细节，保留主记忆点和功能接口 | 为独特堆尖角、飘带、饰物，妨碍转头/开合 |
| 全项目资产争抢注意力 | 让主角/关键道具/核心空间突出，普通对象适度退让 | 强制所有对象高饱和、巨大轮廓或同一特征 |
| 特征只在依据卡或块外说明里 | 补入适用复制正文并核实际视图 | 以“表里有写”或 lint 零退出码当成图上已存在 |

## 4. 状态衍生图计划

为每个资产列出状态版本：`状态名｜首次出现场次｜可见变化｜持续到哪一场｜是否需要独立图`。需要独立图的标准：变化在两个以上 Clip 出现，或变化影响身份识别/动作可读性。一次性、局部的污损由视频正文描述，不单独建图。状态图按 [资产总表](asset-registry.md) 命名，沿用基础图的身份与版式。

## 5. 自查工具

`scripts/asset_basis_lint.py` 检查总表中的依据卡必填项与来源标注、`script_features` 的基础正文覆盖或状态计划指向，以及复制正文的外部片名锚定。有代码围栏时只检查本资产的 `text`/无语言围栏正文，不能用块外依据说明冒充已写入；空围栏不会回退到说明文字。旧版无围栏资产节兼容按整节检查，此时无法自动区分说明与正文，须人工复查。`state:` 仅核已列状态计划，`video` 不验证视频正文，缺文件会说明未核项；不自动判断需求提取是否完整、设计理由是否成立、功能能否实现或实图质量。依据仅存 `project.md` 时由人工核对，不为运行工具新建一套重复台账。
