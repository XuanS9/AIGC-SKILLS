# 项目资产总表与跨批次名称一致性

资产提示词与视频提示词分开交付，共用同一份项目资产总表。所有资产、视频、补镜、改写及分镜任务均执行本规范；样本与完整稿使用同一套名称。登记资产不等于生成资产，也不增加独立确认轮次。

## 生成前读取，交付时继承

1. 先读取用户项目目录已有的 `asset-registry.json`；用户指定的现有资产清单优先。已有清单为其他格式时，保留原始清单，按原名整理为可检查的 JSON，不重新命名。遇到两份清单冲突，先根据已确认交付记录核对；无法确定的条目标记待核对，不自行合并身份。
2. 没有总表时，从当前项目已确认的资产交付、实际文件及用户素材中建立总表。同一对象只登记一个基础调用名；继承旧项目已有名称，新建名称遵守根 SKILL.md 的 S/C/B/P 规则。不从模板示例复制项目名称，不依赖模型记忆重新翻译。
3. 总表写入用户项目目录，不写入 skill 安装目录。无法访问项目目录时，在交付中附可保存的总表，并说明后续会话需要读取该表；不能声称已落盘或能跨会话自动记住。
4. 写资产或视频提示词前都先查表。资产交付标题列出中文名称、调用名及文件或待生成状态；视频的「资产与参考锁定」从总表提取本镜所需条目。样本阶段只写样本提示词，总表登记不提前展开整批资产提示词。
5. 已登记调用名逐字复用，包括大小写、数字、下划线；不得重译、缩写或给同一对象另起调用名。分段正文使用总表中的中文名称和必要可见特征；对白中的称呼可按剧情保留，但不能据此创建另一资产。
6. 文件更新只修改 `file` 和实际状态，保留 `handle`。用户明确要求改名时，同步修改总表及项目内受影响的提示词；无法访问的旧交付列为待同步，不能声称全部修复。

## 文件格式

以下仅为格式示例，不是本项目已有素材，不得直接当作已生成或已绑定的资产：

```json
{
  "schema_version": 1,
  "assets": [
    {
      "name": "阿莉娅",
      "handle": "@C_Alia",
      "file": null,
      "status": "planned"
    },
    {
      "name": "巨蚺",
      "handle": "@B_Anaconda",
      "file": null,
      "status": "planned"
    }
  ]
}
```

- `name`：稳定的中文显示名称。不同对象同名时加可辨识限定词，不把两个对象合并。
- `handle`：唯一逻辑调用名，含 `@`。同一总表不允许重复或仅大小写不同的调用名；允许继承旧项目已有名称。`@Image1`、`@Video1`、`@Audio1` 等编号槽位为保留名称，不登记为项目调用名。
- `file`：实际文件路径或素材标识；尚未生成时为 `null`。相对文件路径以总表所在目录为基准。建议文件名如 `C_Alia_v01.png`，不要把版本号写入逻辑调用名。
- `status`：`planned`（待生成/待补齐）、`available`（实际素材已具备）、`bound`（已绑定当前平台）、`verified`（绑定与引用效果已核验）。后三者必须有实际 `file`；只完成文字提示词时仍为 `planned`，不能升级状态。

总表可增加类型、身份特征、已知别名、基础资产、参考职责等说明字段，但 `name`、`handle`、`file`、`status` 必须保留。别名只用于识别旧称，不是新的合法调用名。状态衍生资产按根规范在后续需要时登记独立条目，并标明基础资产；不因建表批量制作衍生图。

## 视频缺项与平台绑定

- 视频需要而总表没有的关键资产，先查是否为已有对象的别名。确认是新对象才登记 `planned`，注明待补齐；仅登记需求，不附资产生成提示词，不自动开启资产阶段。
- 缺少素材时可继续交付文字方案，明确其待补齐状态。可复制的实际提交提示词仅使用真实可用标签；未生成/未绑定的逻辑调用名只出现在规划清单中，正文可用稳定中文名称描述，不能伪装成可直接引用的素材。模式必需的素材未齐全时，不标记为可提交。
- 项目逻辑调用名与平台槽位分开维护。在每个生成片段的交接清单记录「调用名 → 实际文件 → 当前真实标签/槽位」，例如已实际绑定后的 `@C_Alia → C_Alia_v01.png → @Image1`。槽位可随单次上传顺序改变，不据此修改总表中的调用名，不把上一片段的槽位直接沿用到下一片段。
- 平台支持自定义 Elements 名称时沿用总表调用名，并核对实际附件；只支持编号时使用真实编号。音频、视频及站位参考也可登记在总表中，沿用其已有名称及实际参考职责。

## 交付前核对

每次样本和完整交付都检查：

1. 使用的是当前项目总表，资产标题、视频锁定栏和正文是否指向同一对象。
2. 每个资产调用名是否在表中且逐字一致；不能在视频里另行声明一个新名称来绕过检查。
3. 同一对象是否被换名、重译或重复登记；正文中文名称与身份特征是否一致。
4. 新需求、未生成素材、待绑定项是否明确标记；状态不能靠文字推测。
5. 每个片段的真实平台槽位是否对应正确文件，是否把状态衍生图误当基础资产。

对含资产调用名的提示词，从 skill 根目录运行：

```bash
python3 scripts/seedance_lint.py --preflight --file /path/to/prompt.txt --asset-registry /path/to/project/asset-registry.json
```

检查器对照总表检查未登记调用名、大小写漂移、重复名称及调用名、表结构和待补齐素材；未知调用名即使在提示词内部声明过也会失败。`planned` 引用给出警告，不阻断文字方案评审。未传总表时，报告明确提示未做跨批次核对。

`@Image1`、`@Video1`、`@Audio1`（含空格编号形式）是平台槽位，不作为项目调用名检查；它们的实际绑定按每片段交接清单核对。脚本不验证文件是否上传、不核验视觉效果，也不能可靠识别无 `@` 的正文换称或两个不同名称实为同一对象，必须结合以上人工语义核对。检查通过不等于素材已可提交生成。
