# 视频脚本工作室

## 当前提示词标准与修改纪律

以下是当前交付契约的速查，不另设第二套标准；细则见本入口及 [统一调用与验收总表](references/production-checks.md#统一调用与验收总表)。历史优化记录、旧范本与外部模块不覆盖当前契约，只有用户明确要求的格式/范围例外才按对应分支处理。

- **完整视频（含样本、改写稿）：**只用【参考素材职责】→【一句话概述】→【具体情节】→【全局补充】四段，没参考也保留第一栏并说明无参考；短式仅用于明确精简请求或实际提交硬限制。Clip 用 `批-序`，时长、场景图号等索引放标题，平台设置放复制块外。
- **正文：**概述只用一句话讲本段事件与变化；具体情节按连续秒级时间轴写可见演出、景别/机位、适用光线、运镜与末态。声音紧贴发声动作，原对白以 `说话人+可见状态/气息/语气+说话动词「原句」` 内联；无对白显式写“本段无对白（设计）”，默认 NO BGM、无字幕、无水印。
- **资产与空间：**视频直接用已登记的 `@中文名`，场景图号别名须显式登记；不重写独立资产基础外观，但保留本镜必要状态、地标、路线与接触。逻辑引用不等于真实绑定。跨大空间必须明确切镜或甩镜过桥；用户锁定且可达的一镜到底按具体例外核对。
- **图片：**角色默认六行四格，唯一清晰面部＋三个保留完整头部的全身格，图片不附音色描述或文字标签；B/P 为中性背景多视图与结构；S 为无角色/生物/道具的纯环境。风格继承当前项目，不默认换媒介，也不靠负面词掩盖污染。
- **节奏与范围：**不规定每个 Clip 的分镜数量，也不设单镜3秒上限或固定镜长；镜数与镜长由叙事、动作、对白、表演和可读性决定；每个 Clip／生成组总时长≤30秒是硬上限；超出的内容压缩或顺延到下一个 Clip，不延长单条。模型上限更短时取更短值，在上限内尽量接近30秒，服从叙事与真实动作。阶段内先样本、确认后展开，已确认未变内容复用；单类型不扩范围，原生 JSON/HTML/纯音频按其契约。
- **每次修改后必复查：**新写、修词、补镜、删并、重排、批量替换和Skill维护均执行 [修改后标准复查闭环](references/production-checks.md#修改后标准复查闭环)。重新读取最终落盘稿，核完整改动条目及受影响依赖/接缝，修复后重跑；不能沿用旧版通过记录，也不能只检查改动句或首条样本。每次交付强制核对每个 Clip≤30秒及时间轴完整性；未执行、单条超限或覆盖失败均不得称完成。不按固定镜数、平均镜长或3秒切点强制拆镜，长镜、同镜继续、推近与移焦按实际信息交接和表演需要保留。完整稿/批量修改须附逐条覆盖清单并运行 `scripts/proofread_manifest.py`；清单或哈希不匹配时不得称校对通过。检查记录留块外，不新增用户审批。

## 默认导演决策

视频创作、改写、补镜与分镜默认执行 [导演决策流程](references/directorial-shot-design.md#导演决策流程)：**场景变化与主次 → 观众信息与体验 → 场面调度 → 切镜/镜内交接/停留取舍 → 时长与节奏 → 删除、合并及反向核对**。由助手主动提出并落实合理镜头方案，不等用户逐镜点名。人物目标、判断与代价先有可见行为依据，镜头不能提前宣布未发生的信任、悔改或知情。

**大幅度物理空间转移不得只写成“从A到B”的单画面运镜。**跨房间、跨建筑、室内外、多个地标或行动区域的转移，默认先按 [大幅度空间转移：必须拆镜或用甩镜头过桥](references/directorial-shot-design.md#大幅度空间转移必须拆镜或用甩镜头过桥) 编排为分镜切换，或用明确的甩出→运动模糊→同向甩入→B空间落幅完成过桥。前镜写清离开末态，后镜在新空间重新建立入口/地标并承接到达状态；不让模型在一个清晰画面里同时生成起点和终点。用户锁定的一镜到底才是例外，且必须补可达路线、中间地标、经过时间和摄影机路径。

先看完整戏剧段，再按Clip制作；核心重点需要可读窗口与余波，必要支撑简明交代，连接过程按作用合并。景别、机位、摄影运动、声音和光共同分配注意力；主观、跟踪、操作特写是候选工具，不是事件触发后必须添加的拍法。保持、删并与新增都是导演选择，不能用字数或镜头增长量当优化结果。

决定写入既有project/导演工作单，用户看到简明主方案与关键取舍，复制用提示词仍按四段式。已授权范围内直接实施，不把每个机位变成审批问题；已确认的剧情、对白、揭晓、镜序与一镜到底按实际授权继承。规则归属与执行方法集中在上面的导演决策流程，其余模块按职责引用。

## 导演增强与标准优先级

以本入口的输出契约为准，Seedance 分镜师 3.0 只提供导演工艺增强。完整视频继续用四段式、秒级时间轴、中文资产调用名与 `批-序` Clip 编号；保留阶段内先样本、按场景推进、默认无需回传实图。既有模块里的七类规划信息、九段式、独立声音栏等必须映射到本标准，不能原样替换交付。

视频分镜/改写/编译读取 [导演编译](references/director-compiler.md)：先对齐戏剧意图、可见可听行为与生成表达，再用分镜决策卡核对空间、摄影、表演、光、声音，编译不擅改确认剧情与对白。控制图、关键帧、复杂站位或生成失败时再读 [导演控制与返工](references/director-control-retake.md)，按具体风险选最少控制输入、按证据选择修复出口。工作卡和质检属内部工序，不增加用户审批或项目目录体系。

## 叙事结构先于生成分段

**快切不等于交叉剪辑，生成顺序不等于成片顺序。**视频创作、改写与分镜先按 [多线叙事与交叉剪辑](references/narrative-planning.md#多线叙事与交叉剪辑) 判断单线、并行线及观众获知顺序，再定镜头与生成片段。存在同时追逐、分头行动、救援/倒计时、异地威胁或将要汇合的行动线时，必须评估交叉剪辑；采用或不采用都给出叙事理由，不以平均出场、固定秒数或镜头配额决定。

故事事件先后、成片呈现顺序、素材生成顺序分开管理。角色看不见，不等于观众不能看见；观众看见，也不代表角色已经知情。已确认的揭晓顺序、限知视角、一镜到底优先，改动先在受影响的上游规划中说明，不能在提示词编译时静默重排。只有原剧本分场顺序、没有锁定剪辑时，可以提出交叉呈现方案，不自动把它视为已确认。

**每个 Clip 总时长不得超过30秒；约30秒只是兼容素材的生成效率目标，低于叙事结构与可控性。**超量按[压缩或顺延规则](references/narrative-planning.md#单个clip的30秒硬上限与超量处理)处理，不能用模型支持更长、完整表演或总片长预算为单条超限开例外。不得为凑段延迟另一条必要叙事线，或把交叉叙事还原成“先拍完A再拍B”的成片。按场景推进是制作管理方式，不限制成片剪辑。多空间可按实际能力同次生成，也可分开生成后交叉剪辑；保留成片切点和时段映射，不强塞超量参考。不额外强制出图、建目录或增加审批。

## 默认调用与验收执行

所有视频提示词的新写、改写、补镜与合并生成，先按 [统一调用与验收总表](references/production-checks.md#统一调用与验收总表) 识别适用模块，记录实际读取与正文落点。**有人物即默认调用已有表演与FACS适用部分，无对白、静音和动作镜头也不省略，不等用户提醒。关键表演 beat 按 [物理动作后接潜台词](references/higgsfield-acting.md#提示词编译物理动作后接潜台词) 判断是否需要补一句简短意图，不机械铺满每段。**非人角色接入 [非人表演适配](references/higgsfield-acting.md#非人角色表演适配)，不机械套人类AU；纯景观/产品按实际范围注明不适用。

交付前必须完成文字、提交条件、生成结果三个层级的分项核对；使用“通过／失败／待核验／不适用”四态，证据缺失不能写通过。表演按 [证据验收](references/higgsfield-acting.md#表演证据验收) 落到具体演出句，关键项失败不能用自评分抵消。生成片段先做 [合并与短段例外验收](references/narrative-planning.md#生成分组与短段例外验收)，默认尽量接近30秒；不能把成片短镜直接等同于独立短生成。

调用、分组与验收信息归入现有project/总表，不污染复制用提示词，不新增逐项审批或全套实图门禁。检查适用模块不能越过用户范围；纯Skill维护不改项目文件。

## 工作流程

1. 继承用户已确认的角色、剧情、结局、对白、模型、时长、画幅、语言、速度及素材；缺非关键参数用默认值，只补问影响执行的缺失信息。用户指定的模型与能力边界优先；未指定模型时视频生成默认 Seedance 2.5 `omni_reference`，角色/道具/场景图片及参考视频、音频各按职责输入，无参考时用文字描述主体。严格保留原时间线或接续的已有视频，先核对实际模式能力再处理。
2. 先完整读取 [项目工作区](references/project-workspace.md)、[项目资产总表](references/asset-registry.md) 与 [样本确认流程](references/sample-approval.md)，并读取项目记录指向的当前美术设定。用户指向已有项目工作区时，先读项目目录的 `project.md` 与 `asset-registry.json`，继承已确认的参数、故事、结局、人物、对白、资产名、场景布局、当前阶段与批次进度；未指向工作区或读不到时按新项目处理并说明需提供路径才能继承，不虚报自动记住上次项目。样本与完整稿逐字复用已登记调用名；无总表时从已确认交付建立。识别本次范围：只要基础资产、场景或视频时只交指定类型；完整制作或同时要求多类时，默认统一规划后按「基础资产 → 场景 → 视频」分阶段、按场景推进，不一次展开所有类型。每个阶段的新写、改写、补镜、修词与单条交付先给代表性样本+预期效果，确认后展开当前阶段；样本状态、预期及验证信息留在项目记录或简短交接中，不追加到用户复制用提示词文件；已确认且未变的资产、布局、提示词直接复用，不重复审批。文字确认、实际出图、视觉核对和平台绑定分别记录；默认文字设定及空间布局确认后推进，不要求回传全部资产/场景图。场景与相关视频任务完整读取 [文字空间布局](references/spatial-layout.md)，先锁定“什么在哪里、如何连接”，两类提示词共用同一布局。未看图简注「基于已确认文字布局，实图未核对」，不因此阻止文字定稿；关键设计未定或已有冲突未解决时才将受影响内容标条件性预稿。仅用户明确要求严格验收或出现明显偏差时，核对相关实图。用户明确要求快速预览时才采用联合预稿模式。确认内容、阶段进度与检查证据写回 `project.md`、`asset-registry.json`，可复制提示词存入 `prompts/`；按下方阶段与批次规范执行。
3. 视频创作、改写、分镜、编辑或延伸：区分剧情段落、镜头与生成片段，先做成片叙事和动作时序，再按实际模型容量组段。**每个 Clip 不设固定分镜数量，单镜不设3秒上限或固定秒数范围**；短动作镜、长镜、固定机位与一镜到底均按内容选择，不能因为经过几秒就强制切镜。长对白可持续观察，也可用有意义的反打或相关动作覆盖，保持原句与自然语速；不把30秒换算为必须完成的镜头数。正常实时的扑击、飞行物命中、跌落等必须在真实动作窗口内完成，不能为了插入反应或特写拖长。方法见 [动作同步、接缝去重与整场节奏](references/narrative-planning.md#动作同步接缝去重与整场节奏)。完整读取 [导演编排](references/directing-workflow.md)、[叙事规划](references/narrative-planning.md)、[顶级导演分镜方法](references/directorial-shot-design.md)、[导演模板](references/template-general-director-2-5.md)（其内容按四段式标准格式交付）；完整创作与改写还需 [演出范本](references/template-full-performance-example.md)。分镜先按 [导演决策流程](references/directorial-shot-design.md#导演决策流程) 确定核心变化与主次、观众信息、空间调度，比较切镜/镜内交接/停留，再推导景别、切点和生成片段；紧张题材按快慢落差编排切点而非匀速砍秒，每次切点仍须改变观看任务，不得按固定镜头数或景别轮换机械拆镜。正式剧情按下方「景别与机位服务剧情」主动设计全/中/近景落差、角色表情、关键道具/手部与接触细节，不把空间测试固定广角当默认。空间优先写地标连接、靠山/开阔侧、追逃前后、视线和可达距离（见 [文字空间布局](references/spatial-layout.md#方位描述相对关系优先构图按需固定)）；画面左右、机位高度与角度默认可按参考和动作选择。只有已锁构图、实际参考或关键接触确需时才用当前画面坐标，不让场景图与视频各自规定相冲突的左右。退靠、封路等关键位置变化须有连续动作，特写不重置路线。
4. 打斗、追逐、对抗、演武、人兽战：完整读取 [动作导演](references/fight-director.md)，按需读 [动作设计](references/fight-fight-design.md)、[动作摄影](references/fight-camera-guide.md)、[动作诊断](references/fight-diagnostics.md)。人兽战、兽袭、群兽围攻默认走 fight-director 的高强度奇观编排（升级式动作因果、双向交互、持续状态与动作匹配；仅在原剧情允许处设计奇观，不新增栏目或强制禁收势），并保留因果交锋、双向攻防与真实受力。**追逐必须先锁定被追者在前、追兵在后及共同运动方向；投射物必须写明来源、飞行路径、命中/落点和余态；景别切换必须继承动作相位并有动作、视线、声音或遮挡桥接；跨越大幅度空间时按空间转移规则拆镜或用甩镜过桥，不把追逐路线压成一张混合场景。**支持 Seedance、MiniMax-H3 及通用模型。
5. Higgsfield 任务：完整读取 [平台制作指南](references/higgsfield-guide.md) 与下表匹配的模块，提示词任务另读 [提示词构建](references/higgsfield-prompt.md) 并按其 Load Map 加载。人物出现时加载表演与 FACS；剧情改写加载场景引擎；多场景或分镜加载拆镜模块；对白、声效或音乐加载音频模块。
6. **修改后复查（必做）：**每次新写、改写、修词、补镜、删并或重排完成后，执行 [修改后标准复查闭环](references/production-checks.md#修改后标准复查闭环)。重新读取最终完整稿，对照当前提示词标准逐项检查格式、资产引用、对白与声音、时序、空间及连续状态；批量修改逐条核对，相关前后接缝和下游依赖一起复查。完整稿/批量修改建立逐条覆盖清单，运行 `proofread_manifest.py` 核对范围、结论和最终文件哈希；清单缺项或哈希漂移即复查失败。发现不符合标准的内容先修复，再读回并重跑适用检查；不能只检查改动句、沿用旧版通过结论或通过降低标准消除失败。此步骤由助手主动执行，不等用户提醒，不新增审批；复查结果留在复制块外。
7. **验证与交付：**按「提示词内容边界」将内部规划转成正向描述，执行「输出验证关卡」，检查素材职责、身份、数量、时序、动作因果、连续状态、本镜声源、模型限制及适用约束；修复文本失败项后交付并附验证结果。按 [导演编译](references/director-compiler.md) 反向核对正文能否还原确认分镜及人物任务；连续 Clip 逐缝核对落幅五项，场末快照与未解线头写回现有 `project.md`。失败迭代读取 [导演控制与返工](references/director-control-retake.md)，对照当前证据选择改词、局部编辑、换镜头、改输入或回上游，每轮只改一类变量。

## 一句话概述说明片段主要内容

**【一句话概述】用于让模型先理解本片段发生什么。**用一个完整句子概括“谁在什么情境下，经历/做了什么，产生什么关键变化或结果”；地点仅在理解事件需要时带出。只概括本Clip实际覆盖的内容，不写后续结果，不逐镜复述，不把片段名当概括。风格、景别、运镜和声音放各自的具体情节或全局补充，不塞进概述。禁止使用“镜头从必要空间关系转到动作、接触与角色判断”“末态落在本段已发生的结果”等可套用于任意片段的空泛句。

例：`逃亡者在雪林中夺下追兵的火把逼退士兵，逃跑时踩塌覆雪朽木，连同火把一起跌入捕兽坑。`

## 视频提示词不重复资产基础描述（项目硬规则）

**资产独立创建，视频只负责演出。**角色、生物、道具、场景及已制作的状态/年龄版本，由各自资产提示词与参考图提供形态和外观；视频四个栏目均不重写其五官、发型、服装设计、固有颜色、纹理、材质、体型、解剖结构或建筑造型。尚未生成/绑定也不据此把资产设定抄回视频母稿；登记状态留在项目/总表，提交前完成真实绑定。用户明确选择纯文字生成、没有独立资产时，才补必要主体描述。

**固定资产直接引用：**视频使用 `@角色名`、`@道具名`，不再写“角色名@角色名”或重述五官、服装、材质和基础结构。场景需指向本Clip的具体图：默认沿真实绑定；用户要求按图号直接调用时，可显式登记 `@S01-01` 等作者用别名并使用，别名与实际图片/平台槽位分开记录。普通未建资产的群演、一次性道具及环境构件不编造标签。动作、地标/路径、持物、伤势、破壳、开合和天气光照变化仍必须描述，不能以“避免污染”为由省略演出。

用户明确要求直接@形式的可绑定母稿时，允许使用已登记但尚未绑定的逻辑引用；素材状态留项目/总表，不称已上传或可提交。图号本身不自动变为@引用，具体别名登记与检查见 [总表](references/asset-registry.md#显式场景图片引用别名)。

已确认资产设定、实际可用文件与 `asset-registry.json` 共同维护身份/外观/材质/比例/结构；无实图时不把文字设定称作图中事实。视频提示词不复制五官、发型、服装设计、毛色、材质、基础结构或整段场景布局；但必须从共享布局提取本镜必要的地标关系、路径与空间锚点，不能以“不重复资产”为由省略方位。【参考素材职责】只引用本镜需要的真实可用素材及职责，文件路径与待绑定说明留在块外。

视频提示词只补充本段发生的动态状态：进入/离开、持有/交接、湿污、伤势、破损、遗失、开合、位置、朝向、动作相位与场景破坏。固定场景的具体空间关系来自总表，镜头中的遮挡、路线、受力、变化和破坏写在【具体情节】。资产尚未生成或绑定时，可以写规划用 `@handle` 与中文名；不得把逻辑调用名写成已上传素材。

这样做是为了避免资产文件与视频提示词互相覆盖、产生外观漂移或污染模型注意力。若视频提示词需要自包含提交版本，只补本镜必要的身份锚点，不重写资产基础描述。

## 提示词内容边界

**不输出音色描述。**角色资产、视频、样本及其模板不附固定声线、音高/音质/共鸣/口音档案、英文 Voice Description 或音色标签；旧模块相应描述不进入交付。对白原句、说话人及当下语气、音量、语速、断句、痛喊/喘息/鼻息和现场音效保留，写在实际发声动作处。用户实际提供的音频参考/平台音频ID只按职责和真实绑定调用，不用文字重新设计音色；专门音频任务保留其工具参数，不自动迁入视频正文。

**内部核对剧情，提交正文只写本次要生成的内容。**适用于资产、视频、样本、完整稿及原生 JSON 的生成字段；规则用于助手判断，不逐字附进提示词。

1. **先定生成范围再选内容。**写每个生成片段前，内部列出各时段应出现的角色、道具、状态与必要声音及其进入/取得/离开/丢失节点。项目总表是可用资产目录，不是本镜出场表；只在后续片段出现的对象、状态、标签不进入当前复制块，本片段需要的画外声音照常保留。
2. **把要求写成可见事实。**正文直接描述本镜的天气、受光、陈设和动作；例如写清光源照到的表面、明暗过渡及物件使用痕迹。用户纠正某一项时，先定位该项的来源并调整相关描述，其余已确认的时段、布局与陈设继续继承。「X 不要提前出现」留作内部时序检查，正文只写当前实际登场内容。
3. **片段内晚登场用正向时序。**对象在同一次生成内出现时，资产栏列其职责与登场时段，分段演出在相应节点写入画、取得、交接及状态变化，用"节点前实际持有/场外状态"表达而非"不要提前出现"。例：后续镜头才出现的父亲折刀，当前镜头只写"艾莉娅沿河岸行走、双手摆动"。
4. 资产的无文字/水印、四格单一面部锚点与完整头身、用户要求的静音等输出规格仍按对应格式保留；参考图夹带本镜不需要的对象时，块外指出需裁切/清理/更换，正文只用已确认的目标外观与动作。

## 电影视觉参考匹配

- **先读取项目美术设定。**场景新写、改写和补图先按 [视觉风格](references/higgsfield-style.md#电影视觉参考匹配) 读取项目实际的美术设定文件，继承媒介、时代、文化、影像参考及具体视觉特征。`project.md`与总表记录该文件路径和版本。多参考按项目美术设定明确各自职责；风格缺失时提出方案并写入项目，后续从同一来源继承。
- **剧情定时段，参考定光色。**先提取各段昼夜、季节、天气、室内外与实际光源，再结合用户指定影视参考的地区和场景，确定直射/漫射比例、曝光、色温与阴影。白日、黄昏、夜间分别保留时间特征，夜景的地形、关键动作与接触仍可读。复用地点图继承结构，视频按当前时段与光源呈现门开合、入夜和移动光源的变化。
- **具体风格归项目，Skill负责转译。**作品名称、地区气候、调色、曝光与陈设选择写在项目美术设定；Skill提供读取、编译和核对方法。用户改变风格或修正美术时，先更新该设定及版本，再同步受影响的资产和镜头。正文提取本镜需要的可见特征，直接描述当前受光、材质与空间。
- **逐张进入复制正文。**把参考转成媒介、时代文化/建筑、色彩、材质磨损、光源反差、构图尺度与空气质感，每张场景图选适用特征写入自己的独立提示块，不能只在总表写片名，也不能只写“写实电影/北地/电影感”。按日/夜/室内适配，同一项目保持一致；仅片名、质量后缀或叠摄影词不算画风落地。参考不搬原片角色、生物、军械、载具、地标，不覆盖项目世界观。
- 无实际参考图时标为文字风格参考，按样本确认流程交付。详见 [视觉风格](references/higgsfield-style.md#电影视觉参考匹配)。

## 场景图只交付纯环境（强制）

**场景图中不能出现角色和道具。**S类只生成地形、自然介质、建筑本体与固定空间结构：墙、地面、屋顶、门窗、廊道、台阶、桥体及其结构连接。人物、群演、剪影、动物/生物、家具、货物、日用品、兵器、旗帜、载具/船只、独立器械及剧情道具全部归C/B/P或视频演出，即使在远景、用作尺度参照、已经固定或只是装饰，也不混入场景图。船舱作为场景只生成空舱壳体，船只本体作P类单独调用。

场景复制正文只描述可见环境及空置通道，不写角色/道具名单、摆放和操作，也不点名“由视频加入某物”诱导出图。剧情所需站位、道具落位和固定/接触关系记同一总表的 `video_staging` 或对应Clip，在视频正文按时段落实；已登记物件沿用@引用，不复制外观。固定建筑构件不冒充道具，独立器械不因固定到地面而成为建筑。空场尺度用门洞、层高、台阶、透视和必要尺寸交代，不放人或物作比例尺。人物携带或道具产生的火光只在视频呈现；场景用自然光或明确的场外照明效果，不出灯具道具。

交付前遍历全部场景复制块，核对角色/生物、物件实体、倒影/剪影、远层比例参照和灯具；发现混入先移出并补齐视频落位，复核地标、路径与光线，不以“前景无人”代替整张空场。旧模块允许场景加群演、家具、货物等内容的描述均按本规则转换。

## 资产规范：最小化、命名与衍生图

1. **只为多次出现或剧情重要的对象建独立资产图。**承担身份识别、动作连续性或关键剧情功能的角色、生物、植物、道具、场景可建；一次性、可由提示词直接描述的对象（普通守卫、临时道具等）不单独建。
2. **按职责拆分，四类短前缀：**`S`=场景，`C`=角色，`B`=生物/植物，`P`=道具。专属物件（直升机、标枪等）作 `P`，异兽/捕食植物作 `B`，各自独立调用。
3. **场景图按上节只生成纯环境。**正文写地形、建筑、固定结构、表面磨损、光色和空置通道；洞穴是天然地貌，货舱和居所为空置空间。角色、群演、生物、家具、货物、日用品及剧情道具的实体和落位只在视频呈现。
4. **`B`/`P` 单独制作，不混入具体剧情场景。**以主体及结构为主，使用干净浅色/浅灰背景，不带任何场景、环境道具、人物、影子或叙事地面接触。基础资产提供多视图与结构展示（生物：中性姿态的侧面全身主视图+头部特写+1–3 处结构局部；道具：主视图+补充角度+部件材质局部），版式与示例见 [生物/道具资产多视图规范](references/template-character-asset-delivery.md#7-生物道具资产的多视图与结构)。角色 `C` 的背景与光影按所选媒介确定；选用真人实拍时可保留摄影布景渐变与脚下接触阴影，不套用 `B`/`P` 的无影子规则；`B`/`P` 在视频提示词中通过 `@` 名叠加到 `S` 场景上。
5. **资产调用名与中文文件名统一：**`@` 后直接使用资产中文名本身，与总表 `name` 逐字一致、不加类型前缀，例如 `@艾莉娅`、`@巨型森蚺`、`@标枪`、`@雨林小山峰与河谷`。实际落盘文件名在中文名前加类型前缀与版本号：`类型_中文名称_版本号.扩展名`，例如 `角色_艾莉娅_v01.png`、`生物_巨型森蚺_v01.png`、`道具_标枪_v01.png`、`场景_雨林小山峰与河谷_v01.png`。即 `@handle = @ + name`，文件名 = `类型_ + name + _版本`。视频、资产、场景、项目总表逐字复用同一中文资产名；资产更新只替换绑定文件版本，不改变 `@handle`。
5.1 **资产引用格式：**视频固定资产直接写 `@中文名`，按上节执行；资产/场景身份标题仍可写“中文名紧接同名 `@` 调用名”，即 `中文名@中文名`，例如 `艾莉娅@艾莉娅`、`巨型森蚺@巨型森蚺`、`标枪@标枪`、`坠机斜坡与黑水潭@坠机斜坡与黑水潭`。这样模型既读到中文名（纯文本语义），又保留 `@名` 供平台绑定资产图。不在中文调用名中加数字序号代号；场景图另用 `S01`、`S01-01` 作图片索引，不替代中文 `@handle`。`asset-registry.json` 的 `handle` 字段仍存纯 `@名`（逻辑调用名本身），视频正文不重复中文显示名；资产/场景标题可采用 `中文名@中文名`。资产提示词分节标题写成 `# 中文名（中文名@中文名）`。

5.2 **实际资产文件采用中文命名：**资产生成并落盘时，文件名统一使用 `类型_中文名称_版本号.扩展名`，例如 `角色_艾莉娅_v01.png`、`生物_巨型森蚺_v01.png`、`道具_折刀_v01.png`、`场景_雨林小山峰与河谷_v01.png`。状态衍生资产使用 `状态_基础对象_状态名_版本号.扩展名`，例如 `状态_豪华观光直升机_坠毁翻扣_v01.png`。逻辑 `@handle` 保持稳定，不把版本号写入调用名；`asset-registry.json` 只维护实际 `file` 路径与 `status`，不要求另建项目级命名规范文件或计划文件名字段。普通资产继续按该命名规范；已编号场景图可保存为 `场景_S01-01_中文场景名_视图名_v01.png` 以免混用，既有文件不擅自重命名。保存名、版本和素材状态记在项目/总表，不作为备注塞入干净提示词文件。 
6. **基础阶段只做基础资产图。**伤势、湿污、破损、开合、战斗等状态用"基础图 → 图生图 → 状态衍生图"（如 `角色_艾莉娅_v01.png → 图生图 → 状态_艾莉娅_受伤_v01.png`，逻辑 `@handle` 仍为 `@艾莉娅` 不变），衍生图保持基础资产的身份、体型、材质、颜色与关键辨识特征。
7. **视频提示词分开声明资产职责**，直接引用示例为 `【场景】@河岸`、`【角色】@艾莉娅 @父亲`、`【生物】@巨型森蚺`、`【道具】@家传布`；仅补本段必要状态与职责，不复述基础外观。从总表提取本镜条目、不重命名，缺项标待补齐。规划格式示例：

```text
【场景】@河岸
【角色】@艾莉娅 @父亲
【生物】@巨型森蚺
【道具】@家传布
```

资产只负责身份、结构与视觉一致性；动作、状态写入视频提示词或图生图衍生。基础资产、场景与视频分阶段交付，共用同一份总表及场景布局；单类型请求保持原范围，联合预稿仅用于用户明确要求的快速预览。登记规范见 [总表规范](references/asset-registry.md)。

## 场景内容划分、图号与Clip映射（强制）

适用于场景图交付或视频使用场景参考图；纯文字视频不为满足索引而虚构图片。详细字段与示例见 [总表规范](references/asset-registry.md#场景图编号与clip双向映射)。

- **四种名称分开：**原剧本场号仅作项目溯源；视频继续使用 `Clip 1-1、1-2、2-1`；场景参考用 `S01、S02`，同大场景内内容明显不同的参考可用 `S01-01` 等稳定图号，后缀不强制表示图生图衍生；中文场景调用名仍为 `场景名@场景名`。`S01` 不是“第1批”或平台上传槽位，默认也不自动变为 `@S01`；用户要求直接调用时，须先在总表显式登记对应图片级引用别名。
- **图号唯一且稳定。**只给实际计划独立生成/使用的图分配图号；沿用项目已有图号，不因插入Clip、换文件版本或重排交付顺序重新编号。复用已有图的局部近景不分新号，也不增加生成任务；继承已有编号体系的项目先保持原号，不擅自迁移。
- **实际图生图才标源图号。**独立图号不等于有图生图父级：独立生成的不同环境内容可用 `source_image_id: null`。采用图生图时标真实直接输入，不能仅凭前缀指向母图；源图关系不得自指或成环。共享门口或建筑时继承同一身份和连接，可按已有素材选最少输入，不强制添加控制图。
- **图片与视频双向对应。**场景标题列图号、场景/视图名、必要的母图或图生图标识、源图号及适用Clip；视频标题列Clip、片段名、时长及本片需要的场景图号。一个Clip使用多个场景图时全部列明；若确有按时段切换，用片内时间标注。资源清单不替代分镜顺序，不能用图号代替真实上传标签。
- **按内容划分，先复用再补图。**同一实际空间的换角度、反打、近景、局部放大、相似路段和仅昼夜/光照变化，默认共用一张场景图，由视频按动作补全。环境主体或结构明显不同，如室内桌凳炉坑与门外立面雪院、矿硐内部与泉旁小径，应独立生成参考，即使同属一个大场景。既不每镜一图，也不按大场景名称强制一图。判断与例子见 [场景内容划分与参考复用](references/spatial-layout.md#21-按环境内容划分参考图)。
- **独立参考须说明内容差异。**先判断环境主体和结构是否改变，不能只用“换机位/改夜景”作为补图理由。确有图生图需要时，直接写改变的内容与保持的身份、结构和连接；未使用真实图生图输入，不虚构源图。视频可补全同空间未展示部分，但不随意改入口数量、伤侧或道路连接，不保证模型自动补全必然无穿帮。
- **干净交付。**常用提示词文件只保留上述必要标题、独立可复制正文及需要的独立反向词。源剧本对照、计划表、保存名、备注、确认/生成状态和检查记录放 `project.md` / `asset-registry.json`；不删审计信息、不把未生成素材称作已绑定。阶段样本及审批状态仍在项目记录维护，遵守用户既有文件组织。
- **删除弃用图。**已确定不再引用的场景图从活动场景文件直接删除，不留“可选参考”、空标题或备用生成块；同步视频引用、总表视图/别名/图号、计数与项目当前索引，替换尚在使用的旧引用后检查悬空项。审计信息保留在历史或归档，不作为当前出图任务。
- **登记与核对。**在同一份总表登记 `view_plan[].image_id`、`source_image_id`、实际文件及复用关系，在视频Clip登记 `scene_image_references`。交付前检查图号唯一、源图存在且无环、Clip存在、时段合法及双向映射一致；缺素材仍可完成文字，但图生图执行必须有真实输入图。母图换版只复核其下游图与相关Clip。

标题示例（仅示范索引；实际编号和名称从项目继承）：

```text
# 场景图 S01｜山口／总览（山口@山口）｜母图｜Clip 1-1、1-2（14—30秒）
# 场景图 S02｜长屋／室内（长屋@长屋）｜Clip 2-1（5—26秒）
# 场景图 S02-01｜长屋／门外雪院（长屋@长屋）｜Clip 2-1（0—5秒）
# Clip 1-1｜抵达山口｜时长：30秒｜场景图：S01
# Clip 2-1｜进长屋｜时长：26秒｜场景图：S02-01（0—5秒）、S02（5—26秒）
```

## 场景方位明确化：文字布局先锁定

- 场景与相关视频任务完整读取 [文字空间布局](references/spatial-layout.md)。在现有总表 `layout` 中写一份简短空间底稿：基准视点、固定地标名称/数量/位置、连接关系、高差与必要尺度、行动通道、关键连接可见性及光向；随场景样本一起确认，不另加文件或审批。
- 场景提示词正文按「环境主体 → 地标和连接 → 固定结构与表面使用痕迹 → 动作通道 → 材质/光色/天气 → 可读构图」写。机位、屏幕左右与精确尺寸按动作需要指定；一般用能转身、可超越、能短步退靠等相对尺度。关键桥头、出口和动作通道在母图中可辨，以建筑构件、自然地形与透视交代尺度。
- 视频继承同版地形/建筑身份与连接，按动作自行选择机位和景别。区分固定空间关系、当前画面方位与身体左右；身体左伤翼、右手持刀等事实保持，主体向屏幕左/右行进不必预先锁死。选定实图后按其实际关系配合视频；图文有冲突则修图或同步描述，不拿相反方位文字强压图片。
- 默认无需提交全部场景图。已确认文字布局足以推进文字交付，但不代表出图吻合；明显偏差才局部诊断。总表不会传给模型，本镜必要的空间关系必须写入可复制正文。

## 景别与机位服务剧情

**关键事件必须有意义和余波。**先确定它改变了谁的判断、关系、退路或代价，再选择动作、角色反应、环境/群体变化与决定的必要覆盖，不把事件写成“发生一次就切走”。具体写法与追逐示例见 [事件突出与细节特写](references/directorial-shot-design.md#事件突出与细节特写)。

- **空间统一，摄影自由。**先从已确认剧情中识别环境/关系、行动、关键物件、接触、反应和决定，再为各观看任务选景别与角度；正式剧情不默认全程固定广角或同一中景。详见 [剧情驱动的多景别与多角度覆盖](references/directorial-shot-design.md#剧情驱动的多景别与多角度覆盖)。**大幅度物理空间转移不属于普通换机位，必须调用[大幅度空间转移规则](references/directorial-shot-design.md#大幅度空间转移必须拆镜或用甩镜头过桥)。**
- 全景交代必要空间，中景看清互动，近景/特写交付表情判断、手部操作、关键道具与接触结果；俯拍、低机位、过肩、主观及侧拍按剧情信息选用。每次切镜须交付新信息或改变理解，不按固定景别顺序、镜头配额或平均角色数机械分配。
- **主动设计重点与覆盖。**先按 [导演决策流程](references/directorial-shot-design.md#导演决策流程) 确定整场重点，再用 [覆盖诊断菜单](references/directorial-shot-design.md#主动补足镜头覆盖) 找遗漏。选择停留、镜内交接、切镜、删并的依据是理解、关系、压力与后果；操作/主观/轨迹镜按必要性选用。纯扩写单镜、全片逐条加同类插镜或只增加镜头数量都不算完成导演设计。
- **特写写动作链。**按「谁的脸/哪只手/哪个接触点 → 当下刺激与对象 → 可见变化 → 结果/下一动作 → 衔接」描述。疲惫写喘息、步态与手部用力，恐惧写目光、下颌、肩或呼吸变化；攥拳写手别、收拢、松开或指节受力，避免抽象“坚定/惊恐特写”。道具写持有者、位置与状态改变；持续奔跑/承重不因切特写暂停，伤手和持物不凭空腾空。
- **事件覆盖有差别。**威胁制造者、承受者、旁观者和环境可以提供不同信息；只选已在场、已知情且实际受影响的对象，不平均分配同款惊恐脸。动作结果至少在合适镜头或镜内调度中可读；悲痛和信任留反应时间，爆发不拖慢命中。
- 换角度继承同版布局、轴线与动作相位，必要时重推画面方位和光线投影；特写不必显示全场景，但不能让人物、道具在切回时跳位。当前取景看不见的面部细节/背景不硬写进镜头。
- 保留用户明确的一镜到底、固定机位及风景/纯氛围形式；可用镜内调度、推近或移焦完成信息交接，不强制每段都有脸部/道具特写。不为加镜挤掉必要动作、对白或擅改总时长；导演意图和切点理由留在块外，正文写可见演出。

## 统一规划、分阶段交付、按场景推进

- **阶段0：统一规划。**继承/确定剧情、视觉风格、资产清单、场景布局需求与动作所需通道、高差、尺度，列简明批次目录；规划不是提前输出全部生成提示词，已确认规划不重审。
- **阶段1：基础资产。**共享角色、生物、关键道具先确认设定，按 C/B/P 交付提示词；样本确认后展开当前阶段，文字设定可供后续阶段继承，不要求先回传实图。只做当前需要的基础资产，状态衍生图按需补充。
- **阶段2：场景。**场景仍是 S 类资产。先读取项目美术/风格记录与 [视觉风格](references/higgsfield-style.md#电影视觉参考匹配)，将用户指定电影/剧集和既定媒介转成每张环境图可见的建筑、材质、光色与空气层次；同时把动作需求与资产设定尺度落实为文字空间底稿，再写仅含环境结构、表面使用痕迹与空置通道的提示词；样本确认时锁定布局，后续视频共用。无依赖时可与基础资产并行；有尺度/结构依赖时先协调文字设计，不默认增加实图关卡。
- **阶段3：视频。**继承已确认资产设定与文字布局，先交视频样本、确认后逐 Clip 展开动作、表演、运镜、声音和连续状态，可完成文字定稿。未看图注明实图未核对，未绑定注明待绑定；只有当前片段真实素材绑定与模型条件齐备且无已知冲突时才标可提交。关键布局/动作依赖未定或已有冲突未解时，受影响部分为条件性预稿。
- **按场景推进，不等全片齐备。**共享资产先定稿后，每个场景/连续剧情批次按「补充基础资产 → 场景 → 视频」推进，已有且未变内容直接复用。片段过多时按完整演出负荷再分小批；后续场景只列范围，不提前制作全部资产。只要基础资产、场景或视频时只交指定类型，不强制补做其他阶段。
- **Clip 编号标准（批-序，强制）：**每个视频片段编号为 `批-序`，即“第几批-该批内第几个”，如 `1-1`（第1批第1个）、`4-6`（第4批第6个）、`11-3`（第11批第3个）。批次对应场景/连续剧情段，序号在该批内从 1 累加。Clip 标题以 `# Clip 批-序｜<片段名>` 开头；使用场景图时追加 `｜时长：N秒｜场景图：S01、S01-01`，按上文规则对应到具体图片；`project.md` 的 Clip 序列表用单列“编号(批-序)”。新增片段按所属制作批次给号。重剪已有项目时可保留稳定Clip编号（批次不是成片时间），在同一总表记录 `video_delivery.edit_order`，视频文件与project序列表按该顺序排列；若重新编号则必须同步全部引用并保留旧新对照。不得用旧数字排序恢复已改剪辑。
- 当前阶段工作与交接顺序：批次/阶段与范围（视频含片段号）→ 相关资产与布局、依赖状态 → 当前阶段新增/需修改的提示词（独立代码块）→ 预期效果、检查结果与交接。复制用文件只保留必要标题与提示词正文，其余步骤信息写回项目记录，聊天仅作简短交接。视频使用四段式，具体情节按时间轴分镜、时间段内写运镜；生成片段以接近30秒为编排目标，执行时核验实际模式时长范围。
- 样本交付标明版本与确认范围，然后停下；确认后直接展开当前阶段，不重复询问同一确认。基础资产/场景文字设定及布局确认、提示词交付后，可进入下一阶段样本，不自动等待实图；当前场景视频完整交付后等待用户继续下一批。阶段切换不新增独立审批，下一阶段新内容仍走样本确认。
- **快速联合预览（仅用户明确要求）。**可以联合交付资产、场景、视频的配套样本，确认后展开约定范围的预稿，各用独立代码块；确认仅代表文字方案通过，不代表上游已出图、视觉验收或绑定完成。后续沿同一文字布局完善；实图仅在明确要求或发现偏差时核对，只修受影响内容，不重审已确认未变部分。
- 批量输出多镜时每条保持完整的动作因果、必要取景、声音及接续，不因靠后而缩水为概括；时间戳粒度、镜头密度和强调程度按戏剧主次与演出负荷变化，不能复制首镜的切法或字数。简单连接可以合并，重点和余波须读清。
- 角色资产样本默认单角色六行四格组板（唯一清晰面部特写＋正面/90°侧面/背面完整全身，全身格保留头部、不刻画五官），图底只保留非文字波形，不交音色描述或标签，用户明确要仅定脸或半身时才用局部样本；已指定或纠正的版式持续继承。

## 输出验证关卡

**CHECKPOINT：每次修改后复查当前完整条目及受影响依赖，文本检查失败先修复再重跑；「预期效果」不替代「验证结果」。此关卡由助手执行，不新增用户审批。**详见 [修改后标准复查闭环](references/production-checks.md#修改后标准复查闭环)。

0. 按 [统一调用与验收总表](references/production-checks.md#统一调用与验收总表) 建立本轮适用项、实际模块和证据落点；漏调用或未落实的文字要求先补齐，未生成结果标待核验，不能用不适用回避缺证据。
1. 提取本轮交付约束：类型、范围、版式、已确认身份/服装、状态、时长、素材可用性；区分用户已确认项与助手候选设计。样本只截代表性内容，不把整段剧情压进样本时长。
2. 角色六行组板交付前按 [角色资产模板](references/template-character-asset-delivery.md#六行结构自动校验) 的校验函数核对六行结构与顺序，报告并修复失败项；用户指定的其他格式不套此检查。
3.0 **对白覆盖核对（合并/拆分/改编片段时强制）：**把确认稿（剧本）里的所有台词逐句列成清单，逐句勾到对应 Clip；每句**内联写在它所属 beat 的动作正文里、紧接被说出的动作**，用自然说话句 `说话人+说话动词「台词」`（如 `驾驶员喊「Hold on!」`、`艾莉娅轻声问「May I?」`）写出，台词一律放中文引号 `「」` 内、`「」` 只用于台词。无台词片段显式标注“本段无对白（设计）”，不靠“没写”默认。合并批次、精简或改编后若某句找不到落点即视为遗漏，必须补回或说明删改理由；核对用脚本提取正文所有 `「台词」` 与源真值台词总表按台词文本逐句比对。
3. 语义核对：逐Clip单独读概述，能否明确复述该段主要内容，并与本段分镜起因、变化、结果对应；清除空泛套话、摄影说明、后续剧透及视频四栏中的资产形态/外观复述。保留剧情必要的状态版本、地标/路径、受力接触与图形识别，不把外观去重做成演出删减。基础角色按已确认基础造型呈现，剧情状态与道具按发生/取得/持有/丢失节点核对；遍历全部可复制字段，发现否定句点名范围外对象时删除该句或按「提示词内容边界」改成当前事实。角色板仅一格清晰脸，三格全身保留完整头部、头顶至鞋入画且不刻画五官；六行基础板核图底非文字波形和全图无字，不附音色描述或标签。名称/文件/status 按总表逐项检查，缺项如实记为待补齐。
3.1 **阶段依赖核对：**默认核对上游文字设定、布局版本及变更；不以未回传实图阻止文字定稿。确认存在设计缺口或图文冲突时，只将相关部分标待复核/条件性预稿。可提交状态另核对当前平台绑定与模型条件；纯文字生成路径按用户明确选择及模式能力核验，不伪造资产引用。用户明确选择严格实图验收时仅对约定范围执行，上游换版只复核受影响内容。
4. **空间一致性文本关卡：**场景与视频共享 `layout` 的必要关系，检查地标数量/位置、连接、高差、行动通道是否进入场景正文；构图选择默认可放宽，不为检查强填画面坐标与精确尺寸；逐镜核对机位、起点、路径、终点、朝向与段间继承。画面左右随机位变化，不把母图左右当固定地理坐标；同机位投影与固定空间关系不得自相矛盾。未看图标「文字布局已确认，实图未核对」，只报告文字一致性；已知偏差按 [文字空间布局](references/spatial-layout.md) 局部修图或经确认同步布局与相关视频，不索要全部图片。
5. **调用名一致性（含 `@` 的提示词交付前必做）**：读项目 `asset-registry.json`，对总表运行 `seedance_lint.py --asset-registry` 核对每个 `@handle` 是否登记且逐字一致；缺表或读不到时标「跨批次未核对」、不把逻辑调用名写进可提交提示词，只给中文名描述的条件性方案；资产批次交付时把总表作为交付物回传。
5.0 **场景内容、画风与图号关卡：**逐张核对媒介、时代文化/建筑、固定结构、材质、光色和空气层次是否按项目参考进入复制正文。核光色与参考及剧情时段对应、夜景必要信息可读、整张场景无角色/群演/生物或道具，家具货物/独立器械及其光源归属视频；正文以可见事实表达。再核每张独立图是否确有环境主体/结构差异，同空间视角或光照是否可以复用；弃用图正文与当前登记已删除且无悬空引用。再对场景标题、视频标题和总表作双向核对：独立图号唯一，衍生指向真实计划中的直接源图、无自指或循环；引用Clip及片内时段存在且合法，复用项不新增图号，不能用原剧本场号混充Clip。文字编号不证明素材可用，真实文件与当前平台槽位另核。此项由助手检查，现有名称lint/四段式lint不自动覆盖该映射。
5.1 **事件与细节叙事关卡：**先核 [导演决策流程](references/directorial-shot-design.md#导演决策流程) 的整场变化、重点/支撑/连接、信息顺序、调度与切/留取舍，再逐 Clip 核 [主动镜头覆盖](references/directorial-shot-design.md#主动补足镜头覆盖)。以去说明/去镜头/换视角及整场连读寻找问题，记录新增、保留或删并的具体依据；不能把单镜文字扩写、景别词出现或首条丰富作为全批通过。主观镜核观察者眼位/看向/遮挡，武器操作核准备与真实机制，轨迹镜核释放至接触窗口；时间段不等于镜头或生成任务。再核关键事件是否呈现必要的角色反应、环境余波或行动改变，不能只拍发生而立即重置。再检查是否有关键异常、表情判断、道具操作或接触结果在当前景别看不清，却仍整段只写远/中景；有则调整景别、机位或镜内调度。反向删除无新增信息的重复特写。逐镜核对可见范围、视线/轴线、手别/持有链、动作相位与时长负荷；追逐核对被追者/追兵的前后关系与共同运动方向，投射物核对发射来源、飞行路径、命中/落点和持续余态；不以镜头数量或特写比例作为通过标准。
5.2 **多线叙事与揭示关卡：**先识别本段及相邻段的有效行动线，核对首次露出、回切的新信息、关键揭晓/汇合与选择单线或交叉的理由。开场检查整个叙事单元，不只检查第一个Clip；不得把某角色被遮挡误作观众不可见，也不得用预览声/资产名单冒充另一条线已获得必要画面。切离时其他行动继续，切回核对经过时间、位置、持物、伤势与角色知情；不重演已发生动作。复核改编前后关键事件与对白覆盖、成片时长、图号时段及下游接缝。此为语义检查，现有结构lint不判定交叉剪辑是否合理。
5.2.1 **大幅度空间转移关卡：**逐段搜索跨房间/建筑/室内外、多个地标或行动区域的位移；若正文只有“从A到B”“跟拍来到另一处”而没有明确切镜/分镜或甩镜过桥，先判文字失败并修复。切镜须有A离开末态、交接方式和B重新建立的落幅；甩镜须有甩出方向、运动模糊、同向甩入及B地标收住；一镜到底须有用户授权、可达路线、中间地标、经过时间和高风险记录。检查切换后光向、声场、持物、朝向、速度与空间锚点是否接续，不能用“镜头运动”或时间轴分行代替实际空间交接。
5.3 **导演编译与接缝关卡：**逐镜核对空间、摄影、表演、光、声音在正文的落点，不适用项说明原因；人物反应有刺激与目标，动作有可见反馈。连续 Clip 逐缝核对位置、身体朝向/视线、左右手持物、动作相位/动量、可见情绪与气息；景别切换必须有动作相位、同一视线、连续声源或遮挡桥接，下一镜不得重置主体、追兵或投射物；跨场跳时另有依据。再按 [穿帮高发点逐项排查](references/director-compiler.md#穿帮高发点逐项排查) 核视点可见性、物理可达与手别、资源守恒、通行姿态、距离行程和进出介质：本机位看不见的不硬写、手未空出不做交接、资源数量和归属守恒、低矮通道写出通行姿态、离场者不瞬移回来、换场后脚步/风/光介质跟着变。动作匹配缝保留动势，不为落幅明确而强制收势。编译不能静默增删镜头、改写台词或调整确认的事件顺序。四段式及时间轴可运行 `scripts/director_contract_lint.py`，对白全文对账传 `--dialogue-source`；语义、真实绑定及视觉仍另核。
5.4 **动作时钟与整场节奏关卡：**逐镜检查观看任务与真实演出负荷，不设固定镜数或单镜秒数门槛；“同镜继续”、推近、移焦和分行编号仍计作同一镜头，不伪报切镜。长对白按自然语速持续演出或用有意义的覆盖，不为满足时钟机械加速或切碎。每个 Clip 的总时间轴仍须≤30秒。逐事件核对同时/先后、动作准备与命中窗口；跨Clip连读前尾后首，检查是否重演到达、停步、射击或铃响。对白间等待按镜头总时长而非每个反应分别评估，记录等待理由和角色仍在做什么；检查整场/整集各行动线缺席间隔、故事时间与距离，不把剪辑间隔当行程实测。重排后核对新的相邻接缝、对白顺序、图号时段与总长；秒轴连续不等于动作时序正确。
5.5 **表演与生成分组关卡：**有人物按已有表演/FACS及非人适配逐项核对刺激、注意、表情变化、行动影响、听者、取景可读性与跨镜气息；对面部特写、情绪转折、重要决定及容易演空的动作，核对是否遵循“先物理动作、后潜台词”，潜台词是否简短、直白且没有替代可见证据；没有关键意图或不适用时应省略，而不是为凑格式添加。另核每个 Clip 的标题时长与片内时间轴均≤30秒，超量内容已压缩或顺延且无遗漏；再核上限内的合并候选、短段保留理由及生成→成片时段映射。两项均须具体证据，不以“有表情”或“不注水”概括通过。
6. 附验证记录：`对象与版本｜自动检查结果｜语义核对与待确认设计｜生成/视觉验收状态｜lint 与总表状态`。引用实际运行或阅读证据；无子代理时报单代理核对或 dry_run，无生成结果时写「未生成，视觉未验收」，不虚报独立投票、full_test 或效果通过。

| 触发条件 | 修复 |
|---|---|
| 六行或视图检查失败 | 修正同一样本重跑检查，不以「符合规范」交付失败版本 |
| 字面通过但状态/道具与剧本冲突，或否定句泄漏范围外对象 | 删泄漏句及标签，片段内确需出现的改成正向登场/状态变化，再检查所有字段 |
| 批量后段遗漏关键因果/取景/接续，或全片拍法机械重复 | 回整场重点与演出负荷，补缺失、合并无效覆盖；段长与密度有内容依据，不按首镜字数或切法重写 |
| 景别单一导致剧情信息不可读，或特写只装饰不推进 | 逐Clip找缺失的威胁/操作/接触/反应视角，实际补切镜或镜内信息交接；删重复特写，复核主观归属、武器准备、跨镜状态与时长，不靠增镜配额解决 |
| 生成图全身格多出清晰五官、缺头缺脚或身份漂移 | 按模板局部修复并保留已确认面部，未修复前不标视觉通过 |
| 读不到总表或 `@` 名与总表对不上 | 取得或重建总表并逐字对齐 handle，改正后重跑 lint；始终不可得时只交条件性方案并标「跨批次未核对」 |

## 默认值与输出

- 缺省 Seedance 2.5、16:9、中文。时长继承用户预算；未指定时先按成片演出负荷估时，每个 Clip 硬上限30秒，默认将相容素材合并到不超过30秒（实际模式上限更短时取更短值，超量压缩或顺延到下一条）；每条短生成先评估合并候选并说明保留理由，不能靠放慢、重复或留白注水。编辑继承母片时间线，延伸只估算新增内容。
- **声音并入分镜正文（不独立成栏）：**每个镜头的现场声、动作音效、环境声都写进该镜的动作描述句里、紧贴发出声音的动作，不再单列“声音：”行、不用尾部 `<...>` 声音标签。例：“骨喙撞进机尾、金属被挤出刺耳的呻吟”“她膝盖砸进湿泥、闷响里夹着抽气”。
- **人声必须写状态：**对白写成 `说话人+可见状态/气息/语气+说话动词「台词」`，让“怎么说”和可读的身体状态一起交代，例如 `艾莉娅瞪大眼、猛吸一口气后失声喊「What?」`、`父亲压着气音、几乎说不出「I know.」`、`守卫厉声喝「Drop it.」`。台词仍放中文引号 `「」`、`「」` 只用于台词。
- **惊恐/情绪写成可见表情与身体，不写标签：**不写“惊恐”“害怕”“痛苦”这类抽象词，改写具体表情与身体反应——瞳孔骤缩、眼睛瞪大、眉峰拧起、脸血色褪尽、嘴半张、下巴发抖、呼吸乱、肩猛地缩起、手指抠紧等，落在当前景别能看清的线索上。近景写脸部微表情，远景用头肩姿态、步态与呼吸表达。
- **对白内联在动作发生时刻：**台词写在【具体情节】对应 beat 的动作正文中、紧接触发它的动作，写成自然说话句 `说话人+说话动词「台词」`（说话动词随语气变化：`喊/问/低声说/嘶吼/轻声问/唤` 等），使“何时说、在哪个动作说、什么语气”一目了然；台词放中文引号 `「」` 内，`「」` 专用于台词、不用于其他描述，便于脚本提取核对。跨批次合并、精简或改编时按“对白覆盖核对”逐句回对确认稿并重跑核对脚本，防止台词丢失。无台词片段显式标注“本段无对白（设计）”。
- **【参考素材职责】栏只放参考用途与本镜新增内容：**该栏列出本片段出现资产的直接引用，如 `@艾莉娅 @巨型森蚺 @坠机斜坡与黑水潭`；采用已登记的图片级场景别名时可写 `@S01-01`，不能混用不同视图。`@handle` 由平台绑定到对应资产图，模型据此获得身份、外观、结构；**不要在提示词里写“沿用资产文件/asset-registry”“身份以资产图为准”“规划母稿/待绑定”等元描述——这些文件不会传给模型**。除 `@handle` 外，本栏只补本镜的登场/状态/新增内容（湿污、伤势、持有、破损、翻扣、进入/离开等），或写清由基础资产图生图衍生的状态。身份与基础外观不重复描述；时段按剧情理解需要进入概述或具体情节；视觉、运镜、声音进入【具体情节】或【全局补充】，连续性进入【具体情节】和【全局补充】。真实参考素材需排除背景/多视图时，排除项放块外说明。无对应 `@` 资产的一次性对象（临时守卫、临时道具）直接用文字描述。
- 完整视频按**四段式标准格式**交付：【参考素材职责】（独立资产用直接引用及必要职责/状态，其他参考按需注明用途；`X 对应 @图片N` 须有真实映射）→【一句话概述】（一句概括本片段的主要事件、关键变化或结果，便于模型理解）→【具体情节】（**优先秒级时间戳 `0s-3s：`**，每段写景别+机位、当前取景可见的空间层次与运动、主体动作含肢体/幅度/速度及可读的表情或物件细节、光影写入本段正文（光源方向、硬柔与对比，不新增栏目）、运镜起手→路径→落幅与衔接、段末明确结束状态）→【全局补充】（一致性、跨段继承、字幕/水印/声音开关）。四段承载原七类内容、信息不减（映射与声音/字幕符号表、授权短式见 [叙事规划](references/narrative-planning.md) 的“一套规划，按任务输出”）。每段描写足够丰富，按当前景别写可见细节，面部近景写微表情、道具特写写操作与状态，不向远景或局部特写硬塞不可见的脸部/全景；情绪靠动作表情表达，不写观看任务、切点依据等内部规划。身份/数量/归属/朝向/损伤/破坏累计等跨段状态融入具体情节的段间承接与全局补充，不单列连续性栏。声音写在其发生的时间段内、紧贴发声动作；对白统一用 `说话人+可见状态/气息/语气+说话动词「台词」`，音效与音乐写成自然句（不单列声音栏、不用 `{台词}`/`<音效>`/`(音乐)` 尾部标签、不堆片尾）；非中文台词先注明语言；跨镜声场一致性由后期处理；默认 NO BGM。**视频一律不出现字幕（无字幕、无水印）。负向描述主要用于声音与字幕开关，其余限制优先转成正向事实。模型、画幅、时长、速度等平台设置写在提示词代码块之外，正文不另加【模型与规格】【规格】等栏目。**
- 样本确认后动作默认交付高强度、慢节奏、中间型三套方案；标准/极速为独立速度轴，用户只选一套则只交该套。完整参数见 [导演编排](references/directing-workflow.md)。
- 角色资产完整读取 [角色资产模板](references/template-character-asset-delivery.md)，参考 sd-asset-engine 的角色方法，保留六行图片正文；默认全图共4格：唯一清晰面部特写＋正面/90°侧面/背面完整全身，三个全身格保留头部且不刻画五官、头顶至鞋入画，按年龄与风格写头身比，端正站立、双手空着，不加局部特写格。图底仅非文字波形，全图无文字标签，不交音色描述。换装只改指定造型、复用身份；用户已有音频参考或TTS设置只按真实输入记录，不转写固定音色段落。**是什么风格就用什么风格，不默认真人或任何固定媒介**：用户明确指定优先，其次继承项目已确认风格，已有风格不重新选择；仅风格缺失时根据内容题材、叙事气质与用途推荐，随当前样本确认；题材不等于媒介，“写实”也不自动等于真人。只有选定真人实拍方向，才用“真人演员服装定妆照”及自然肤质、真实材料、适配项目的摄影布光与接触阴影；中画幅/85mm/颗粒按需。二维、插画、三维（含写实 CG）、定格分别使用对应线条、画材、渲染或工艺描述，不统一去 CG。真人出现 CG 感时优先清理正向提示词污染：删除或替换混入的渲染展示语义、过度完美材质与空泛质量后缀，保持原定风格、身份和服装，不靠叠加摄影词抵消污染。即使工具支持独立负面栏，也不以负面提示词解决这种风格污染；以 CG 为目标时保留其渲染语言。
- 原生 HTML 分镜、代码动画、纯音频、图像及 [双语 JSON](references/seedance-bilingual-json.md) 按对应格式交付，默认无字幕、无水印、无未要求的旁白。
- 参数来自对应模型资料，快照过期或无法核验时标待核验；当前环境仅处理本地文本并提供执行交接，不把外部操作写成已完成的生成或验证。

## 参数、模板与检查

- 模型参数：[视频](references/MODEL-SPECS.md)、[图像](references/IMAGE-MODEL-SPECS.md)、[音频](references/AUDIO-MODEL-SPECS.md)。其他：[模型选择](references/model-guide.md)、[图像模型方法](references/image-models.md)、[摄影词汇](references/vocab.md)、[提示词示例](references/prompt-examples.md)、[Photodump 预设](references/photodump-presets.md)。
- 题材、站位、地图、文字叠加与各模式模板在 references/template-*.md，按 [平台制作指南](references/higgsfield-guide.md) 选用。
- [共享约束](references/negative-constraints.md) 作为内部诊断菜单，按「提示词内容边界」转成当前镜头必要的正向描述，不直接追加预防词句；[制作检查](references/production-checks.md) 用于交付与单变量迭代。
- 本地提示词检查（Python 标准库，从 skill 根目录运行）：

```bash
python3 scripts/seedance_lint.py --preflight --model seedance_2_5 --file /path/to/prompt.txt --asset-registry /path/to/project/asset-registry.json
```

覆盖过滤风险、结构及已知模型参数；传 `--asset-registry` 时另做跨批次名称核对。脚本不代替身份语义核对、真实绑定检查与视觉验收。

四段式文本契约另检（单个复制正文，或含 `# Clip 批-序｜片段名` 和独立代码块的多 Clip 文件）：

```bash
python3 scripts/director_contract_lint.py --file /path/to/video.txt
# 单 Clip 可附 --duration 30；全部对白覆盖检查需提供同范围真值稿（台词用「」）
python3 scripts/director_contract_lint.py --file /path/to/video.txt --dialogue-source /path/to/confirmed-dialogue.txt
```

检查四标题顺序、时间轴连续与终点、每个 Clip≤30秒（声明时长和时间轴均检查，未声明时仍检查）、显式无对白标记（不检查固定分镜数量或单镜3秒上限）、旧式声音标签及台词出现次数；标题可追加时长与场景图号，但该脚本不校验S图号、源图关系或图文双向映射，须按上面的场景图号关卡另核；不解析项目圣经中其他范围的台词，单样本只对照同范围摘录。该检查仅用于标准四段式文本，不套原生 JSON/HTML、图像或纯音频。

用户素材从其实际路径读取，生成文件写入用户项目目录；不移动原始素材，不向 skill 安装目录写项目文件。接收其他创作包的确认稿时保留 copyVersion、正文、人物世界设定、不可改项与待定制作规格。
