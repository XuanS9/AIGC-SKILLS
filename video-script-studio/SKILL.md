# 视频脚本工作室

## 工作流程

1. 继承用户已确认的角色、剧情、结局、对白、模型、时长、画幅、语言、速度及素材。缺少非关键参数时采用默认值；只补问会影响执行的缺失信息。用户已明确指定的模型与能力边界优先；当前项目未指定模型时，视频生成默认 Seedance 2.5 `omni_reference`：角色、道具、场景等图片及参考视频、参考音频各按职责输入；没有参考时用文字描述主体，不要求准备开头/结尾画面，也不把任意图片设为视频起点。已有视频需要严格保留原时间线或接续时，先核对实际模式能力，再单独处理。
   资产、视频、分镜及其改写任务均先完整读取 [项目资产总表](references/asset-registry.md)，读取用户项目内同一份 `asset-registry.json`；没有总表时从已确认交付及实际素材建立。样本和完整稿逐字复用已有调用名，交付前对表核对；分开生成不另起名称。
   提示词任务先完整读取 [样本确认流程](references/sample-approval.md)，识别本次类型：要求资产只写资产，要求视频只写视频；同时明确要求两类时分成独立批次，分别给样本、确认和交付。每次先交本次类型的代表性样本及预期效果，停止并等待用户明确确认，再输出对应批次全部提示词；新请求、改写、补镜、修词及单条交付均适用，历史确认不替代本次确认，不设跳过样本的例外。
2. 视频创作、改写、分镜、编辑或延伸：先区分剧情段落、镜头与模型生成片段，默认向 30 秒模型上限凑段、单个生成片段尽量承载连续多阶段的动态内容；按观看任务、动作因果及表演负荷编排片段内的切点与节拍；具体方法执行 [按内容拆镜与估时](references/narrative-planning.md#按内容拆镜与估时)。完整读取 [导演编排与交付](references/directing-workflow.md)、[叙事规划](references/narrative-planning.md)、[八栏目模板](references/template-general-director-2-5.md)；完整创作和改写还需完整读取 [演出范本](references/template-full-performance-example.md)。
3. 打斗、武打、追逐、对抗、演武、人兽战：完整读取 [动作导演](references/fight-director.md)，按需读取 [动作设计](references/fight-fight-design.md)、[动作摄影](references/fight-camera-guide.md)、[动作诊断](references/fight-diagnostics.md)。人兽战、兽袭、群兽围攻、演武群战默认采用 fight-director 的高强度奇观编排（升级式奇观纲要 + 行为与交互铁律栏 + 按回合升级分镜 + 禁收势尾帧 + 完整负面提示词栏），同时保留因果交锋、双向攻防与真实受力。支持 Seedance、MiniMax-H3 及通用模型。
4. Higgsfield 任务：完整读取 [平台制作指南](references/higgsfield-guide.md) 和下表匹配的模块。提示词任务另须完整读取 [提示词构建](references/higgsfield-prompt.md)，按其 Load Map 加载模型与任务资料。联合动作任务先编排动作因果、空间和角色状态，再转换为平台格式。
5. 人物出现时加载表演与 FACS 身体微反应；剧情改写加载场景引擎；多场景或分镜加载拆镜模块；对白、具体声效或音乐同步加载音频模块。非动作任务沿用对应原生流程。
6. 按下方「提示词内容边界」将内部规划转成当前生成任务的正向描述，再执行「输出验证关卡」，检查素材职责、人物身份、数量、时序绑定、动作因果、连续状态、本镜声源与画面对应、实际模型限制及适用约束；修复文本失败项后再交付，并附实际验证结果。失败迭代根据当前素材诊断，每轮只改一类变量。

### 缺素材、参数冲突与样本退回

| 触发条件 | 当轮处理 | 仍未解决时 |
|---|---|---|
| 项目没有 `asset-registry.json`，或登记名有而文件未交付 | 从已确认交付建立同一份总表；把无文件条目标为待生成/待绑定。仅凭已登记的调用名或用户口头列出的参考素材类型不能认定文件已在当前环境可访问、已上传或已绑定；逐项核对 `status`、`file` 和本片段平台绑定。某条资产只提供名称（即使声称“总表有这个名”）而没有 `file`、`status` 和本片段实际绑定时，该条一律按未绑定处理；连看似可沿用的角色标签也不直接写进代码块。未绑定或待补的调用名只列在规划清单；样本提示词正文用总表中的中文名称描述（如阿莉娅、狼）；可复制的提交提示词仅使用当前真实可用的标签，并写明素材前提 | 无法核实名称时询问原名；缺必要文件时交待补素材清单与条件性样本，不声称素材已上传或提示词已可直接生成 |
| 只有一张或少量参考图、视频或音频，未提供其可见/可听内容；或参考与模型限制冲突 | 把已提供素材按角色身份、道具结构、场景布局、动作/运镜、对白/声音等职责登记为普通参考；不因数量少而转为起点画面模式。先给只描述已知内容的条件性视频样本：正文使用“人物参考图/场景参考图/动作参考视频/环境声参考音频”等职责称谓，在样本外标注待核对的文件和绑定；缺少总表或槽位仅阻止真实提交，不阻断文字样本；素材未展示时不捏造角色/生物外观、场景细节、数量或新增事件；参考视频里的多名主体不等于本片主体数量（“狼追逐”不擅自扩写成狼群），也不把未核验的素材写成“已绑定”；时长冲突按内容拆片 | 无法读取关键参考时仍交可评估的条件性文字样本及待补清单；不编造画面、对白、素材槽位、上限或生成结果，仍遵守本批次样本确认 |
| 本批次样本被要求修改或确认范围不明 | 只修订当前类型和范围的样本，标新版本并等待明确确认；资产与视频分开记录 | 未获本次确认时停在样本阶段，不展开全片、三强度方案或另一类型提示词 |

## 提示词内容边界

**内部核对剧情，提交正文只写本次要生成的内容。**本节适用于资产、视频、样本、完整稿及原生 JSON 的生成字段；参考模板中的“排除项”“关键约束与排除”和负面词示例均受本节约束。规则及反例用于助手判断，不逐字附进提示词。

1. **先定生成范围，再选内容。**写每个独立生成片段前，内部列出各时段应出现的角色、道具、可见状态和必要声音，以及进入、取得、离开、丢失的节点。项目总表是可用资产目录，不是本镜出场表。只在后续片段出现的对象、状态及标签不进入当前复制块的任何栏目；本片段需要的画外对白或声音照常保留，按声音职责描述。
2. **把禁令还原为当前事实。**用户或剧本写“X不要提前出现”时，将其作为内部时序检查，不转抄到生成提示词。当前范围无需X时直接省略X及对应排除句，连同别名、标签、倒影/影子等变相点名一并删除。画面有必要约束时，用已确认的动作、构图或状态描述；没有依据就省略，不另编姿势、物件或事件来凑正向句。
3. **片段内的晚登场保留正向时序。**若对象确实在同一次生成内出现，资产栏只列其职责与实际登场时段，分段演出在相应节点写入画、取得、交接及状态变化。片段内也不用“不要提前出现/不要提前交接”等否定时序句，改写为对象在节点前的实际持有或场外状态。例：内部“父亲和折刀不要提前出现”若指后续镜头，当前镜头只写“阿莉娅沿河岸行走，双手随步伐摆动”；若属于当前片段，则写“0–3秒阿莉娅望向林间；3秒父亲从右侧入画，手持折刀；5秒父亲递出折刀，阿莉娅右手接稳”，并可写“第5秒前折刀由父亲持有，第5秒开始转移至阿莉娅右手”。不因删否定句而删掉登场、递交因果或丢失后的连续状态。
4. **全字段检查，空项省略。**资产锁定、总合成、演出、连续性、结尾交接及约束栏都按当前范围写；交接只写本段结束时的实际状态，不预告下一镜的对象。保留八栏目结构时，第八栏只写必要且未重复的当前约束；无新增约束则留空栏，原生可选字段则省略，不为填栏补排除清单。素材缺项、后续安排与验收理由放在复制块外，正文不夹带制作说明。
5. **参考图污染先处理素材。**若参考确实带有本镜不需要的道具、角色或剧情状态，块外指出需裁切、局部清理或换用匹配的参考，保留原文件；正文只用已确认的目标外观与动作。素材尚未处理时给条件性文字样本，标明待处理/待绑定，不声称文字否定能抵消图中物件，也不假称已修复。仅需名称时不推测参考里有什么。

**反例与边界：**不写“不提前出现折刀/父亲”“没有背包、标枪”“无受伤、无破衣”等剧情实体或后续状态清单；不把这些词搬到同一提交包的负面提示词栏，也不把本节反例当作固定黑名单附给每个项目。当前确实需要的人物、道具、伤势、对白和声音正常描述。本规则不等于删除所有“不/无”：资产的无文字/水印、无头取景及用户明确要求的静音等输出规格仍按对应格式保留；独立负面栏仅在模型支持且有明确需求时使用，不自动填入后续剧情实体。

## 电影视觉参考匹配标准

- 为剧情项目编写场景资产或视频提示词前，先按题材、世界环境、情绪和动作规模匹配一部具体电影作为主视觉参考；用户指定的参考优先，已有选择直接继承。用户未指定时给出一个推荐，并融入本批次样本，不新增独立审批步骤。
- 不能只写“大片感”“电影级”或只报片名。必须把参考转化为可执行的色彩、光源与反差、构图与尺度、空间纵深、材质与空气质感；按日景、夜景和室内条件适配，同一项目保持视觉一致。详细方法见 [视觉风格](references/higgsfield-style.md#电影视觉参考匹配)。
- 参考只负责视觉语言，不覆盖已确认的人物身份、服装、时代、剧情、空间和画幅，不自动搬用参考电影的角色、生物、军装、载具、地标或场面。场景资产仍为纯环境图；角色、B/P 孤立资产沿用各自背景规范，不为匹配电影而增加叙事背景。
- 示例：《绝境雨林》的雨林场景以《金刚：骷髅岛》（Kong: Skull Island，2017）为主视觉参考，提炼巨物尺度感、厚重热带植被、暖色日光与深绿阴影、潮湿材质及分层薄雾。皇室贵族度假身份与服装保持；不引入原片军事元素。此例仅适用于匹配的项目，不作为所有题材的固定画风。
- 片名是创作方向，不等于已上传视觉参考、平台预设或效果已验证。没有实际参考图时标为文字风格参考，不虚构素材槽位；仍按当前批次样本确认流程交付。

## 资产最小化、命名与衍生图规范

1. **只为多次出现或剧情重要的对象制作独立资产图。**反复出现、承担身份识别、动作连续性或关键剧情功能的角色、生物、植物、道具和场景，可以制作资产图；一次性、非关键、可由提示词直接描述的对象不单独制作资产图。普通守卫、医护、驾驶员、临时搬运人员、普通树枝、碎木和一次性文件等，默认不建立独立资产。
2. **资产按职责拆分，不混合制作。**使用四类短前缀：`S` = Scene 场景，`C` = Character 角色，`B` = Beast 生物/植物，`P` = Prop 道具。
3. **场景图必须是干净环境图。**场景图只包含地形、建筑或固定空间结构、植被、岩石、泥潭、固定环境、光线、天气、时间状态和可行动区域；不得包含角色、猿人、动物、异兽、捕食植物、专属道具、人物或动物影子、文字、数字、标牌或水印。直升机、运输笼、标枪、折刀等专属物件必须作为 `P` 资产独立调用；巨蚺、古鳄、翼兽、巨蛙和捕食植物必须作为 `B` 资产独立调用。
4. **`B` 与 `P` 单独制作资产图，不混入具体剧情场景。**生物、植物和道具图以主体及其结构为主，可使用干净中性的展示背景（中性灰阶、简洁棚拍展示环境等），背景不喧宾夺主；不放雨林、泥潭、树枝、水面、笼舍、战斗现场等具体剧情场景，不加入环境道具、人物或动物，不保留叙事性地面接触。是否透明或带展示背景由图像工具与后续合成需要决定，不强制透明抠图底。植物若必须展示根系、附着结构或底部形态，只保留主体自身结构，不带土壤、树干或雨林环境。**同时，`B`/`P` 基础资产不能只给一张动态或单一角度图，要像角色组板一样提供多视图与结构展示：**生物默认中性展示姿态（自然舒展、水平陈列或自然站立，非战斗、攻击、盘绕缠斗、张口等动态），提供侧面全身主视图 + 头部特写 + 1–3 处关键结构局部（鳞片/皮肤材质、背部或腹部纹路、口部或四肢/尾），展示完整解剖比例、颜色分布与辨识特征；道具提供主视图 + 至少一个补充角度（侧/背/俯之一）+ 部件与材质局部。具体版式与可复制示例见 [生物/道具资产多视图规范](references/template-character-asset-delivery.md#7-生物道具资产的多视图与结构)。
5. **角色图与生物/道具图的背景规则分开。**角色组板可按角色资产模板使用干净浅色背景；`B` 与 `P` 不使用角色组板式场景，不加入布景、道具陈列或环境氛围。它们在视频提示词中通过 `@` 名称叠加到 `S` 场景上。
6. **统一使用简短稳定的调用名。**逻辑调用名使用：`@S01_River`、`@C_Alia`、`@B_Anaconda`、`@P_Spear`。实际文件名使用：`S01_River_v01.png`、`C_Alia_v01.png`、`B_Anaconda_v01.png`、`P_Spear_v01.png`。视频提示词调用稳定的 `@` 名称，不直接依赖版本号；资产更新时只替换实际绑定文件版本，不修改全部视频提示词。
7. **本阶段只制作基础资产图。**伤势、湿污、破损、囚禁、开合和战斗状态等衍生图不在基础资产阶段展开，也不默认批量生成。后续需要时，必须采用“基础资产图 → 图生图 → 状态衍生图”，例如：`C_Alia → 图生图 → C_Alia_Injured`、`C_Ape → 图生图 → C_Ape_Caged`、`P_Cage → 图生图 → P_Cage_Open`。衍生图必须保持基础资产的身份、体型、材质、服装、颜色、结构和关键辨识特征。
8. **视频提示词分开声明资产职责。**从项目资产总表提取本镜条目，不重新命名。以下仅为规划格式示例，实际提示词须核对素材可用状态及真实平台绑定；缺项标记待补齐，不伪装成已绑定资产：

```text
【场景】
@S11_RiverBank
【角色】
@C_Alia
@C_Father
【生物】
@B_Crocodile
@B_Anaconda
【道具】
@P_FamilyCloth
```

资产只负责身份、结构和视觉一致性；动作、伤势、湿污、破损、开合和即时状态写入视频提示词，或在后续阶段通过图生图建立状态衍生资产。资产图与视频提示词仍按本 Skill 的样本确认流程分开交付，但必须共用同一份项目资产总表；资产确认不自动授权视频提示词交付。中文名称、稳定调用名、实际文件与可用状态按 [总表规范](references/asset-registry.md) 登记；项目调用名与平台槽位分别记录。

## 分类型写，先样本后完整提示词

- 资产请求只给角色、道具或场景资产样本；视频请求只给镜头或短片段样本。视频可说明已有资产与缺项，不附资产生成提示词；资产交付后不自动进入视频阶段。类型不明且上下文无法判断时先澄清。
- 给出本批次类型与范围、样本版本、可复制样本提示词、预期效果及确认请求，然后停止。用户提出修改时先改样本，再等待确认；仅有文字时不声称已经生成样图/样片或验证实际效果。
- 用户确认本批次当前样本后，直接输出该类型、该范围的全部提示词，不重复要求样本确认。新一轮提示词请求重新给样本；资产和视频各自确认，一类的确认不授权另一类。
- 完整输出的格式、三强度方案、角色六行与多视图等要求在本批次确认后执行；模块中直接交付、工具自动串联或无附言的建议不得绕过本流程。详情与原生 JSON 等格式适配见 [样本确认流程](references/sample-approval.md)。
- **批量展开多镜时保持逐镜等密度。**一次性输出多个镜头/片段的完整提示词时，每个镜头都独立按 [按内容拆镜与估时](references/narrative-planning.md#按内容拆镜与估时) 完成分段演出：分段时间戳粒度、每段的画面/运镜/声音细节密度与首镜及已确认样本一致。不因镜头排在后面就把分段合成更长的整段（如前镜 2–3 秒一节、后镜突变成整个 8 秒一句）、减少分段节点或压缩成概括。后段用更少更长的段，必须有“该镜动作确实更简单”的内容依据，不是因为位置靠后或篇幅疲劳。镜数多或全片较长时，从末尾镜头开始写仍需保持同等密度，必要时先列逐镜分段骨架再逐一填充。
- 完整批次在样本确认后展开；样本必须体现本次待验证的格式，不能以「样本阶段」省掉用户指定的多视图。角色资产样本默认采用单个角色的完整六行组板（左侧正面面部特写、右侧无头正面/侧面/背面），用户明确要求仅定脸或半身时才采用局部样本。本条优先于参考文件中默认半身样本的建议；用户已指定或纠正的版式持续继承，不重复询问。其他类型仍按 [样本确认流程](references/sample-approval.md) 交付，不提前展开全部提示词。

## 输出验证关卡

**CHECKPOINT：文本检查失败先修复再交付；「预期效果」不能替代「验证结果」。此关卡由助手执行，不新增用户审批。**

1. 写作前提取本轮交付约束：类型、范围、版式、已确认身份/服装、基础或衍生状态、时长及素材可用性。区分用户已确认项与助手候选设计；示例人物的身份和服装不得当作项目设定。样本只截取代表性内容，不把已确认的整段剧情压缩成样本时长，例如40秒开场不能为交8秒样本而重演全部铺垫与袭击。
2. 人类角色组板必须核对六个实际非空行及其顺序：总述→姓名/年龄/性别→左侧正面面部→右侧无头三视图→背景/一致性/无文字→灯光/质感。自动换行不算新行。运行以下 Python 标准库检查，`text` 为即将交付的完整代码块内容；报告各失败项。用户指定的其他格式不套此检查。

```python
def validate_character_sheet(text):
    import re
    lines = [line.strip() for line in text.splitlines() if line.strip()]
    if len(lines) != 6:
        return [f"六行结构失败：实际{len(lines)}行"]
    checks = [
        ("总述分区", all(x in lines[0] for x in ("角色资产参考图", "左侧", "面部特写", "右侧", "无头"))),
        ("独立身份行", bool(re.search(r"\d+岁.*(?:女性|男性|女|男)", lines[1])) and not lines[1].startswith(("左侧", "右侧"))),
        ("正面面部", lines[2].startswith("左侧：") and "正面面部特写" in lines[2]),
        ("无头三视图", lines[3].startswith("右侧：") and all(x in lines[3] for x in ("无头", "正面", "侧面", "背面"))),
        ("背景与同一身份", "背景" in lines[4] and "同一" in lines[4]),
        ("无文字约束", all(x in lines[4] for x in ("不出现", "文字", "字母", "数字", "姓名", "视图标签", "尺寸标注", "签名", "水印"))),
        ("灯光与质感", "光" in lines[5] and "质感" in lines[5]),
    ]
    return [name for name, ok in checks if not ok]
```

3. 格式通过后进行内部语义核对：基础角色按已确认的基础造型呈现（用户指定状态优先），剧情状态与道具按发生、取得、持有、丢失节点核对。遍历全部可复制字段，逐个确认实体及状态在当前生成范围是否需要；发现用否定句点名范围外对象时，删除该句及其标签，或按「提示词内容边界」改成有依据的当前事实，再核对一次。不能只搜“不/无”一律删除；同片段晚登场、合法输出规格和画外声音均须保留。右侧无头意为取景裁切，保留颈根以下至鞋底，不表现身体断面。名称/文件/status 按资产总表逐项检查；缺表、缺文件或未绑定必须如实记为未检查或待补齐。
4. 提示词之外附简短验证记录：`对象与版本｜自动检查结果｜语义核对及待确认设计｜实际生成/视觉验收状态`。必须引用实际运行或阅读证据；检查脚本未覆盖的项目不能算自动通过。现有 `seedance_lint.py` 的视频检查不能替代上述角色组板检查。严格 JSON 等原生格式将记录保存在旁附文件，不破坏用户要求的 schema。

🔴 **CHECKPOINT · 调用名一致性（含 `@` 的资产/视频提示词交付前强制执行，防止资产名与视频里 `@` 名对不上）：**
   - a. 定位项目总表：读取用户项目目录的 `asset-registry.json`。本会话读不到（新会话、未提供、跨批次丢表）时，先要用户提供，或从已确认交付重建总表；**总表未就位不得把逻辑调用名写进可提交提示词**，只给用中文名描述的条件性方案并标注「跨批次未核对」。
   - b. 交付前对总表运行跨批次核对，不跳过：
     ```bash
     python3 scripts/seedance_lint.py --preflight --model seedance_2_5 --file /path/to/prompt.txt --asset-registry /path/to/project/asset-registry.json
     ```
     核对视频/资产正文每个 `@handle` 是否在表中且逐字一致（大小写、数字、下划线）；未登记名、大小写漂移、重复名即为 FAIL，先改正再交付。脚本抓不到无 `@` 的中文换称与「两名实为一对象」，须再做一次人工语义核对。
   - c. 资产批次交付时，把 `asset-registry.json`（含各 `handle`、`status`）作为交付物一并给出/回传，并说明后续视频批次须读回该表逐字复用；不声称已跨会话自动记住。无法写入项目目录时附可保存的总表文本。
   - d. 记录里如实写 `lint 是否运行｜总表是否就位｜@名核对结果`；未跑或缺表时写「跨批次未核对」，不得声称调用名已一致。
5. 无独立子代理时只能报告单代理语义核对或 dry_run；无生成工具/结果图时写「未生成，视觉未验收」。不得宣称独立投票、full_test、图像效果通过或给出虚构提升分数。错误样本至少回查半身替代组板、总述与身份并成五行、基础图含剧情状态三种失败；用户明确要求半身时必须允许该例外，不能用修复制造新的格式错误。

| 触发条件 | 当轮修复 | 仍未解决时 |
|---|---|---|
| 根规范、样本建议与用户版式发生冲突 | 用户明确要求优先；无用户特例时按本入口的样本版式执行 | 只询问确实无法从上下文判断的格式，不重复确认已定项 |
| 文本六行或视图检查失败 | 修正同一个样本，重新运行格式检查 | 不以「符合规范」交付失败版本，列明具体阻塞 |
| 字面检查通过但状态/道具与剧本冲突，或否定句泄漏范围外对象 | 删除泄漏句及标签；本片段内确需出现的对象改写为正向登场/状态变化，再检查所有复制字段 | 素材本身夹带对象时在块外列待修素材，正文给条件性样本；不追加否定清单 |
| 批量输出时后段镜头分段变长、时间戳节点骤减或画面/运镜/声音细节明显少于前镜 | 视为逐镜密度退化，按首镜等密度重写退化的后段，补齐分段节点与三项细节 | 确属动作更简单才减段的，在分配表注明内容依据；不以篇幅或位置为由合段 |
| 生成图右侧仍有头部或身份漂移 | 按角色模板局部修复并保留已确认面部 | 未修复前不标视觉通过；文字检查结果不能替代图像验收 |
| 本会话读不到项目总表，或视频/资产 `@` 名与总表对不上（未登记名/大小写漂移/换名） | 先取得或重建 `asset-registry.json` 并逐字对齐 handle，改正后重跑 lint；资产批次把总表作为交付物回传 | 总表始终不可得时只交用中文名描述的条件性方案，标注「跨批次未核对」，不把逻辑调用名写成可提交或声称一致 |

## 默认值与输出

- 用户明确要求优先。模型、画幅和提示词语言缺省采用 Seedance 2.5、16:9、中文。时长继承用户已确认的全片及局部预算；未指定时生成片段默认以模型单次上限（Seedance 2.5 约 30 秒）为目标，单片段尽量承载连续多阶段动态内容。多个相邻镜头优先合并进一次接近 30 秒的生成；靠真实连续动作填满，不靠均分留白、机械翻倍或放慢动作注水。长动作超过模型单次上限时才在可交接的动作相位分段。编辑继承母片时间线，延伸只估算新增内容，并遵守相应模式限制。
- 普通完整视频按八栏目交付：资产与参考锁定、一句话总合成、全局视听与空间、主体行为与节奏规则、分段演出、连续性、结尾状态与交接、关键约束与排除。全局视觉与动作规则写一次，保留分段行动、响应及同时/先后/触发/持续等时序关系。每个独立生成的分镜仅指定本镜实际需要的环境声、对白和动作音效，声源随本镜画面变化；不得指令模型继承前一镜的声音或控制全片音轨。默认 NO BGM；用户明确要求音乐时，分镜仍以现场声为主，整片配乐连续性另交后期混音。跨镜声场一致性由剪辑和后期处理，不宣称分镜提示词能保证。
- 样本确认后，动作默认交付高强度、慢节奏、中间型三套完整方案；标准/极速为独立速度轴。用户只选一套则只交该套。完整参数、角色资产格式及交付检查见 [导演编排与交付](references/directing-workflow.md)。
- 角色资产完整读取 [角色资产模板](references/template-character-asset-delivery.md)，保留六行提示词、左侧面部与右侧无头三视图、身份与材质锁定及无文字图像要求。
- 原生 HTML 分镜、代码动画、纯音频、图像及 [双语 JSON](references/seedance-bilingual-json.md) 按对应格式交付；同一内容不重复附加长稿。默认无字幕、无水印、不添加未要求的旁白。
- 参数和专有术语来自对应模型资料；快照过期或无法核验时明确待核验项。当前环境仅处理本地文本并提供执行交接；不把外部操作参考写成已经完成的生成或验证。
