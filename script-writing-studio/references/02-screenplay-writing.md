# 完整剧情正文写作

独立接收灵感、大纲、外部剧本或已知项目材料，不要求先运行开发模块或使用固定档案。适用于3–30分钟的单片/单集及局部续写、改写。先执行 `00-preflight.md`，完整创作同时读 `19-runtime-structure.md` 与 `15-dramatic-tension.md`。

## 2. 正文原则

- 默认M1标准影视稿，说明/动作简体中文，对白英文；用户指定优先。M2小说化稿服务阅读，不自动改变剧情类型。单片/单集、类型、平台、时长与叙事密度分别选择，不混成一套默认。
- 事件有因果，人物行动带来后果与新选择；每场有信息、事件、关系或策略变化。冲突来自真实目标和施压能力，不靠全员降智。
- 按叙事张力模块保持有效攻击、反应和回报。需要尖锐时敢于写阻挠、嘲讽和反击，不将对抗磨成礼貌观点交换，也不强制每场羞辱或爆发。
- 可靠解释可以解决唯一的信息缺口；利益、能力或关系阻力仍在时不能听懂就服从。不强制受挫、成长、和解、洗白或统一升华。
- 无对白、单人、治愈、喜剧、悬疑或群像选择各自机制，不强加反派和悲剧。知识通过可见证据改变选择，不插讲课段，不拿错误技术增加张力。
- 副线与人物过程按故事需要建立，不能只为填满30分钟。保留重要决定前的判断与决定后的反应，不按生成秒数删对白或将每场切成预告片。

## 3. 来稿与续写

按 `16-copy-confirmation.md` 核事实与明确保留项，可重构场序、攻防、对白与有效反应，不只逐句换词；授权只诊断、只精修或确认稿原样制作时不扩大范围。准确直接引语不得伪改，戏剧化对白与史料区分。

续写继承时间线、人物所知、称谓、道具、伤势、服装、关系和未兑现承诺。缺非关键细节合理暂定；改变题材、结局、核心关系或用户锁定事实先确认。已明确修订不重复问，但新稿仍需按确认规则交回。

## 4. 交付与检查

按 `04-screenplay-format.md` 的剧本总表 + 场次表交完整场次、可见动作和完整对白，不用梗概代替正文。这里必须区分交付目的：梗概用于让用户确认剧情走向，只概述关键事件、选择、后果和节奏；完整剧本用于展示剧情细节，必须把每个已确认的关键事件扩写为可见、可听、可表演的连续动作—反应回合，写清空间关系、受力、失手、意外、反制、人物判断、对白和声音结果。仅写“某生物袭击”“豹人救下女主”“两人逃脱”等结果性句子，即使放进大表格，也仍然是梗概，不算完整剧本。按 `06-writing-delivery.md` 核结果格式与覆盖范围；一行一个动作—对白回合，保持先后及同期关系，不由表格行数推定镜头数。按实际语言和动作核算自然片长，目标、估算与实测分开；开场有观看理由，中段持续变化，结尾兑现或留下合适余韵。检查主副线因果、人物策略、信息顺序、回报、连续性及事实边界。

3–30分钟长稿按完整场界分批，已交范围与剩余接续点清楚；批次不等于分集，不逐批强制确认，不承诺后台自动续写。正文不截断，未交部分不能以摘要冒充完成，用户要求全稿则持续完成授权范围。

按文案确认规范交copyVersion与明确确认范围，助手自检不代表用户确认。确认后的生产设计可交脚本包Skill，文案模块不读取制作技术库；同步可委派画布Skill，未确认稿不能覆盖旧版生成输入。维护Skill不写作品画布，不自动生成。
