# 正文写作、分批与交付

> 3–30分钟完整作品按 `19-runtime-structure.md` 确认具体单片/单集目标、全片覆盖与长内容接续；局部任务只处理相关范围，不强制跑其他Skill。

## 1. 执行流程

1. 复用已有材料，内部确认任务范围、设定、语言、时长与待核项。
2. 继承或暂定模式、节奏类型、密度档位、分集开关；仅问关键缺口。
3. 按 `15-dramatic-tension.md` 写完整事件、对白与动作。按题材进入 知识叙事/历史核验/专业核验。
4. 检查因果、人物行为、情感张力、承诺回报、可拍性与时长；修实际问题。
5. 按 `00-preflight.md` 的本阶段条件完成文案；按 `16-copy-confirmation.md` 交付完整正文与必要附注，标待确认版本。用户明确确认后委派脚本包Skill；同步委派画布Skill，仅交文案与管理状态。维护Skill不写作品画布。

不输出启动自检报告、不等待重复的“开始”，不以用户没选菜单为由停写。M1/M2 格式见 `04-screenplay-format.md`。

## 2. 修改循环

按用户反馈修改命中范围，保留未改部分和连续性。用户要完整回稿就给完整回稿，要局部替换就给定位清楚的替换内容。仅当重大方向或改动范围不清时追问，不每轮强制询问“是否满意才进入下一场”。

用户在长稿中途提出修订，先处理影响后续的修改再继续；明确要求后置的问题按其安排记录，不能一边沿用失效设定一边声称最后再处理。

## 3. 长稿分批

依据实际输出规模与场景完整性分批，不把8000字、3集或任何数量当模型统一硬上限。短任务直接完成；长任务先说明分批范围并交第一批，不额外等授权。

- 优先在完整场次、单集或自然事件边界分批，不强制按三幕切成四批。
- “批量模式”表示在当前可交付范围内连续推进、不逐批审批；不能承诺离开本轮后会在后台自行继续发送。
- 已完成、剩余与接续位置真实标记；未写内容不以摘要冒充完整剧本。
- 输出容量需要后续轮次时明确接续点，不以“注意力必然衰减”为由缩减已授权任务。

## 4. 最小充分交付

正文按 `04-screenplay-format.md` 默认交剧本总表与场次表，场号与行号稳定；一行一个动作—对白回合，不将表格行当镜头或生成段。预计时长按对白与动作估算，不靠文学稿字数或“一页一分钟”机械换算。标题、预计时长、版本与必要附注可简洁呈现。

文案须独立完整交付并标明唯一主稿；用户明确确认前不展开生产表。未完成内容标剩余范围，文案完成不宣称整包完成。

创作笔记按需记录核心情绪、取舍、真实风险和下游提醒，不强制自找缺点、DNA引用配额、统一收束语、CTA或全量自检表。

文案修改与确认后的最小叙事交接按叙事张力整合：本段任务、人物目标与阻力、新增事件、情绪触发、可见回报及段末状态。专业事实、确认稿台词、关键反应和动作条件不能在交接中丢失。

## 5. 对外结果格式契约

按请求范围交结果，不把以下清单变成每次全量输出的固定流程。讨论可直接回答；正式交付先给对应成品，必要解释后置。正文写作前仍执行已定梗概确认门槛；表格排版不代表文案已获确认。

| 当前任务 | 默认结果 | 完成标准 |
|---|---|---|
| 创意 / 方案比较 | 方案表：一句话故事、冲突机制、情绪价值、结局方向、制作差异与推荐依据 | 选项有实质差异，不把候选说成确认 |
| 人物 / 世界观 | 按角色或规则分类的设定表：身份、目标、阻力、关系、行为/语言与连续性边界 | 属于文案设定，不称图片资产包 |
| 梗概 / 分集大纲 | 按因果顺序的故事表：目标、关键事件、选择与后果、信息变化、结尾、预计时长 | 大纲不能替代已请求的完整正文 |
| 正式剧本 / 完整改稿 | 剧本总表 + 场次表，完整动作、对白、声音、时序及场末状态 | 不输出只有故事摘要的表格；只有用户明确指定阅读稿等其他格式时改变容器 |
| 会诊 | 问题表：严重性、场号/行号、原文依据、具体问题、可用修订方案 | 只列实际问题；用户仅要诊断时不擅自改全稿 |
| 局部修改 / 对白精修 | 替换结果表：场号/行号、人物、完整替换动作或对白、必要声音/状态 | 替换表即唯一新稿；原文对照与理由按需附后，不要求用户从批注拼正文 |

表格渲染交付，不把 Markdown 表包在代码框内当成阅读结果。单元格过长则按回合拆行或按场拆表；换行可用 `<br>`，文字中的竖线须转义，不能把一整场拆坏或截断对白。表头可按局部任务缩减，但已用字段不留无解释空格；确实没有写“无对白/无”，未知写入待确认项而非编造。说明与动作默认简体中文，对白默认英文；用户语言要求优先。

交稿附一张简短交付状态表：版本、请求范围、实际已交范围、剩余范围（无则写无）、确认状态及真正阻塞项。局部任务只核局部覆盖；整剧请求不能只给开场示例就报完成。事实来源、合理假设、改编边界单列，不进入角色对白。文案文本齐全、用户已确认和制作可用是不同状态。

交接传递唯一主稿及其场号/行号、确认范围、语言与保持项；下游不得只拿交接摘要代替全文。人物身份原义、已定时代/世界观、场合与身份显露/隐藏状态一并保留，可定位到确认来源；用户最新明确纠正不得被旧摘要覆盖，助手造型建议不算已确认事实。身份不擅自降格或升级，未定爵位/职业等关键项如实标明；本阶段不代写制作造型。用户未要求作品落盘时不创建文件；已授权画布同步委派画布Skill，维护规范时不写作品画布。
