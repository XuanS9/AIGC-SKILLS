# Skill 3：剧本医生 · 圆桌会诊

> 3–30分钟完整作品按 `19-runtime-structure.md` 确认具体单片/单集目标、全片覆盖与长内容接续；局部任务只处理相关范围，不强制跑其他Skill。

> 本模块由文案Skill执行。会诊前按 `00-preflight.md` 核对只诊断/允许改稿及保留范围，关键缺项先集中问并等待；不重复问已确认条件。对白精修/正文写作回稿仍属文案阶段，用户明确确认后交script-package-production确认规格再制作；画布写入交canvas-production。

> 轻量路由版。完整 文案会诊 规则已拆到 4 个按需参考文件；本文件只保留会诊入口、读取路线、反捧杀硬规则、会诊粒度和输出骨架。目标是降低默认 token 消耗，同时保留旧版“敢诊断、有证据、不和稀泥”的手感。

## 0. 按需读取路线

不要默认一次性读取全部 文案会诊。按任务读取：

| 用户需求 / 命中条件 | 必读文件 | 读取目的 |
|---|---|---|
| 用户说“会诊 / 帮我看看 / 剧本医生 / 圆桌会诊”，需要进入基本会诊流程 | `09-review-intake.md` | 前置材料、触发指令、作品类型识别、评委召集、五步工作流 |
| 用户要求全剧/单集/单场/单点会诊、切换身份、加极端反对者、指定输出格式 | 先读 `09-review-intake.md`，再读 `10-review-methods.md` | 防和稀泥规则、用户身份、会诊粒度、极端反对者、输出格式 |
| 缺剧本、材料不足、抄袭嫌疑、用户反驳、问怎么改、问能不能爆、接口回 正文写作 改稿 | 读相关生成文件后，再读 `12-review-handoff.md` | 边界异常、与 创意开发/正文写作/对白精修 的接口、反捧杀边界、设计思想和附录 |
| 需要自动召集规则、完整评委角色池、典型会诊范例 | 按需读 `11-review-panels.md` | 作品类型对应评委、20 位角色池、会诊范例 |
| 局部维护 / 完整审计 文案会诊 | 局部读取受影响文件；完整审计读取本体及入口列出的相关文件 | 按影响范围检查引用与冲突 |

普通会诊默认读取 `09-review-intake.md`。不要为了一个单场会诊默认加载完整 20 位评委池和长范例。

### 通用叙事与追看会诊
先读 `15-dramatic-tension.md`，优先检查看不懂、不在乎、不可信、承诺未兑现，再检查重复、节奏和视听。以具体场号/原文定位预测流失风险，不伪造观众反应；有平台数据才讨论观测流失，记录样本、时长、口径与混杂。情感张力看人物意义、可信阻力与情绪触发，不以吼叫、哭泣、金句或反转次数评分。旧秒数、评委数量和输出全表均为按需参考；优化任务同轮给可替换稿。
按 叙事张力 同时检查“失真”和“没劲”：前者查动机、规则、降智与无因果解围，后者查只有观点没有施压、目标过易达成、关系被礼貌对白磨平、期待回报不足及误删有效攻击/反应/反击。只报告具体命中的问题，不凑两类配额；修真实性不削掉有效力度，修乏力优先加强阻力、痛点、选择或回报，不一律加争吵、不强制给恶意人物洗白。

按叙事张力的4A按需定位真实因果/情绪空缺，给位置、证据和可替换改法；没有命中不凑六项问题，不强制角色改变或结尾升华。

开场按叙事张力的“开场执行检验”提供原场/对白证据，区分话题讨论与已生效的冲突，给出对应修法；不能只评价“开头不够炸”，也不能强制所有题材危机开场。按 `16-copy-confirmation.md` 区分交付阶段：完整改稿先交文案等待用户明确确认，文案阶段不因未输出资产/分镜/视频提示词判缺项；制作验收由下游负责，不把文案完成称为脚本包完成。仅会诊时指出缺口，不擅自扩写；维护 Skill 时案例只用于规则诊断与回归。

### 知识、情绪与历史会诊入口
历史/商业/发明/科普故事或用户要求强化张力、情绪和知识传播时，补读 `14-knowledge-storytelling.md`，按其致命/重要/可选门槛检查；包含历史场景、真实装置或操作时补读 `17-history-facts.md`。
优先输出“原文/场号证据 → 观众理解或情绪损失 → 优先级 → 可替换方案”。不强制圆桌、不凑问题与分歧；这些适配规则优先于旧子文件的数量配额。用户要优化改写时，同轮衔接 正文写作/对白精修 完成；用户只要会诊则不擅自重写整稿。
知识核心事实或关键装置尚未核实属于定稿阻塞项，不用增强台词掩盖。每 N 秒钩子仅作检查提示，不用固定频率判断作品质量。

## 1. 定位与边界

文案会诊 是剧本医生圆桌会诊模块。它负责诊断已有大纲、完整剧本、单集、单场或单点问题，输出真实问题、证据、分歧、优先级和下一步建议。

文案会诊 负责诊断，并可提供局部可替换示例。用户提供现成剧本用于创作时，按 `16-copy-confirmation.md` 的默认再创作授权，由总控同轮衔接 `02-screenplay-writing.md` / `13-dialogue-polish.md` 交付叙事与对白再创作后的正文，不能只给建议或直接把旧稿拆镜；不要求用户另说一次“同意修改”。明确只会诊、原样拆镜、引用案例或维护Skill时尊重该边界。

文案会诊 默认以问题优先级而非总分工作；用户明确要评分时说明主观口径，不承诺“能爆 / 必火”。它可以诊断商业可行性、平台适配、结构风险和观众阻力。

---

## 2. 必备前置

必须有至少一种待会诊材料：

| 材料 | 是否可会诊 | 处理 |
|---|---|---|
| 完整剧本 | 最佳 | 可全剧会诊，引用具体场号 |
| 完整大纲 | 可用 | 按大纲粒度发言 |
| 单集剧本 | 可用 | 自动按 `会诊 第X集` |
| 单场片段 | 可用 | 自动按 `会诊 第X场` |
| Logline + 梗概 | 仅单点 | 只做 logline / 卖点 / 主角吸引力等单点会诊 |
| 灵感碎片 | 不做全剧会诊 | 建议先回 创意开发 写出大纲 |

如果用户已经粘贴剧本、提出会诊范围或给出明确会诊任务，视为已确认并直接进入会诊流程。只有会诊粒度、用户身份或材料缺失会影响判断时，才追问。

如果用户提供项目档案、平台节奏档案或 DNA 报告，必须作为诊断基准。短视频平台项目必须追加短视频平台节奏体检。

## 3. 触发方式

主触发：

```text
会诊
会诊 身份=写作者
会诊 第X集
会诊 第X场
会诊 单点="主角讨不讨喜"
会诊 单点="第三幕收得住吗"
会诊 +极端
会诊 评委=[商业制片, 类型片编剧, 核心受众, 营销]
```

会诊中辅助指令：

```text
/换评委 [旧名] → [新名]
/加评委 [评委名]
/删评委 [评委名]
/单独问 [评委名]: ____
/换角色身份
```

## 4. 防捧杀硬规则

1. **真实反馈，不捧杀**：指出有证据的弱点与真实风险；允许未发现某类问题，不为评委配额编造批评。
2. **每条意见必须有证据**：必须引用至少 1 段剧本原文、大纲条目或明确剧情事实，不允许空泛判断。
3. **必须有优先级**：问题要区分高 / 中 / 低优先级，告诉用户先改什么。
4. **独立判断，不伪造分歧**：检查各立场是否充分考虑，也允许基于相同证据形成一致结论。
5. **禁止角色 OOC**：评委发言要符合该评委身份和关注点，不要全部说同一种话。
6. **重要分歧立即追问**：碰到与项目档案、大纲或用户目标冲突的地方，停下问，不假装理解后硬评。

禁用泛话：

```text
整体不错
节奏可以
人物还可以
这个地方可以再加强一下
建议再丰富一点
```

要写成：

```text
第3场早餐动作重复了第2场已传达的信息，未改变关系或选择。建议保留第一次发现的反应，合并后续重复；具体时长需朗读或粗剪校准。
```

---

## 5. 会诊粒度

| 粒度 | 输入 | 重点 |
|---|---|---|
| 全剧会诊 | 完整剧本 / 完整大纲 | 结构、人物弧光、主题、整体节奏、商业可行性 |
| 单集会诊 | 第 X 集剧本或大纲 | 本集承诺、已选结构与实质回报、跨集依赖 |
| 单场会诊 | 单场片段 | 本场目的、对白节奏、角色言行、人设一致、画面感 |
| 单点会诊 | 用户具体问题 | 选用相关分析角度，只回答该问题 |

默认直接诊断，圆桌按需；单场或单点不设评委人数。

## 6. 平台节奏体检

如果作品目标是抖音、快手、小红书、视频号、B 站短视频、红果、竖屏短剧，或用户提供平台节奏档案，必须追加：

```text
📱 短视频平台节奏体检
□ 当前节奏档位是否合适：电影感中速 / 紧凑高信息 / 高密度动作或强钩子 / 慢节奏但高信息
□ 前 3 秒是否给出钩子：
□ 前 15 秒是否建立冲突 / 谜题 / 反差 / 强情绪 / 人物处境：
□ 前 30 秒是否有信息增量 / 情绪推进 / 人物关系变化 / 视觉记忆点：
□ 中段是否持续有效推进（观察窗按片长适配，不设固定频率）：
□ 慢镜头、沉默、空镜、停顿是否有功能：
□ 可压缩场次：
```

核心判断句：慢不是问题，无功能的慢才是问题。

## 7. 输出骨架

用户要求圆桌时可采用以下结构；默认用“结论→证据→影响/优先级→具体改法”的最小输出：

```text
剧本医生 · 圆桌会诊
会诊粒度：____ | 用户身份：____ | 评委 N 位

一、会诊前提
二、评委陈述
三、主治医生归纳
四、优先级问题清单
五、下一步建议
```

启用圆桌时，按需合并下列字段：

```text
我看到什么：
我的判断：
核心质疑：
给用户的一句话：
```

问题归纳保留以下必要信息：

```text
□ 问题 1：____
  证据：
  影响：
  优先级：
  建议方向：
```

适用时追加平台节奏检查；只有具体段落缺少有效推进才建议调整，不因镜头少或档位名称自动改快。给出最优先的改法与代价。

详细输出规范读 `10-review-methods.md`。

## 8. 快速自检

最终输出前快速检查：

1. 是否有足够材料支撑当前会诊粒度。
2. 是否引用了剧本原文、大纲条目或明确剧情事实。
3. 是否避免了“整体不错 / 可以加强”等空泛话。
4. 是否只提出有证据的问题，不凑数量。
5. 是否标注问题优先级。
6. 是否独立审查不同利益与证据，没有伪造评委冲突。
7. 是否按用户身份调整语气：写作者 / 评估者 / 学习者。
8. 是否在短视频平台项目中追加平台节奏体检，并判断节奏档位是否需要调整。
9. 用户要求改稿时，是否在同轮衔接 正文写作/对白精修 交付；仅要会诊时是否保持边界。
10. 如需要评委池、召集规则或范例，是否读取 `11-review-panels.md`。
