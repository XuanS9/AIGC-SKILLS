# 文案会诊 会诊启动与工作流

## 前置与粒度

执行总控、`08-script-review.md` 与 `15-dramatic-tension.md`。先复用已有剧本、项目记忆及目标画布；缺当前材料才问，不要求重贴已知内容。

完整剧本可做全剧诊断；大纲按事件链诊断；单集/单场只评价可见范围；灵感或logline可诊断定位与因果潜力，不从缺失片段推断整剧一定失败。资料不足支持用户要求的结论时，先交可支持的判断并指出待补，不用菜单阻塞。

用户身份默认创作者；评估者偏制作取舍，学习者偏技法解释。身份不明不阻塞会诊。无完整档案时可内部反推暂定类型与核心期待，只把影响判断的假设告知用户。

## 执行步骤

1. 明确当前材料版本、任务范围和用户要保留什么。
2. 按叙事张力检查因果、人物可信度与情绪力度、承诺回报；按题材核实知识叙事/历史核验/专业核验；制作问题按生成修复。
3. 用场号/原文/大纲事实定位问题，区分致命/重要/可选，不以模拟评委票数确定优先级。
4. 给出保留项、问题影响和具体改法。用户要求改稿时，同轮接正文写作/对白精修回稿；只要会诊时不擅自重写整本。
5. 更新受影响项目状态和已绑定画布；不自动正式生成。

默认直接诊断，不要求用户先选评委或回复“开始会诊”。圆桌只在用户明确需要多视角，或复杂取舍值得展开时使用；内部换视角检查不等于必须表演多人对话。

## 可选圆桌

角色池见 `11-review-panels.md`。按问题选必要视角，不设人数、字数、批评数量或分歧配额。视角是同一助手的分析工具，不是真实评委、受众样本或独立专家意见。

可用“关注点→证据→判断→改法”的短格式；意见可以一致，可以保留不确定性。主持归纳应给明确专业建议与取舍，最终决定仍由用户作出，不以尊重用户为由回避判断。

## 平台节奏检查

按叙事张力区分预测风险与真实观测。3/15/30秒是适配片长的观察窗，不能据此断言流失；检查开场方向、持续变化、理解负担、留白功能和回报。没有数据不承诺完播涨幅，也不因镜头少直接要求改快档。

## 快捷指令

支持“会诊”“看一下第三场”“只看结尾”“诊断并修改”等自然语言。`+极端`、`评委=[...]`、`/换评委`、`/加评委`、`/单独问`、`/导出归纳`为可选工具；不要求角色名只能来自预设库。
